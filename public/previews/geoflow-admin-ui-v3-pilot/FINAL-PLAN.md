# GEOFlow 管理后台 UI V3 最终升级方案

## 1. 目标与验收口径

以当前 `geoflow-ai-workspace-prototype.html`、`geoflow-sidebar-layout-prototype.html` 和 Admin UI V2 的 `design-lock.json` 为唯一视觉基准，将现有 83 个登录后管理页面统一为固定左侧导航与右侧工作区结构，并新增 1 个 AI 工作台入口。

完成后的核心验收口径：

1. 84 个登录后页面共享同一个公共壳层、导航定义和设计变量。
2. 左侧栏在右侧长页面滚动时保持固定，菜单区内部可滚动，账户区固定在底部。
3. 所有页面的选中菜单、权限、返回路径、面包屑和最近处理记录正确。
4. 登录页与主题生成预览页保持独立结构，但复用颜色、字体、控件和状态规范。
5. 现有 254 条后台路由、表单字段、权限、CSRF、验证、导出和轮询行为保持兼容。

## 2. 评审后补充的关键事项

### 页面清单必须由真实路由生成

当前后台有 254 条管理路由、97 条 GET/HEAD 路由、85 个可视页面，其中 83 个使用后台公共壳层。生产实施时建立路由清单生成脚本，标记页面、接口、下载、跳转和预览类型，避免后续新增页面脱离公共导航。

### 原型与真实后台需要先对齐

现有 Admin UI V2 静态包有 84 个页面状态。全量实施前补齐 4 个托管站点页面，合并旧安全设置跳转页，并将 AI 工作台、404 和主题预览标记为特殊页面状态。

### 权限属于布局能力

83 个公共壳层页面中有 23 个仅超级管理员可访问。菜单、最近处理、快捷设置、面包屑和页面操作都必须使用同一套权限判断，避免出现可见但无法访问的入口。

### 最近处理需要隐私和稳定性约束

最近处理最多显示 3 条，按管理员账户隔离，过滤无权限路由，不保存密码、Token、搜索词和记录详情参数。删除目标记录后，历史项自动失效。

### 长表单需要离开保护

网站设置、文章编辑、分发编辑等长页面增加未保存提示、页内分区导航、错误锚点和保存状态提示。验证失败后定位到第一个错误字段，并保留用户输入。

### 表格需要统一密度和溢出规则

宽表格允许容器内横向滚动，操作列在桌面端保持可见，数字右对齐并使用等宽数字。移动端优先保留任务名、状态和主要操作，其余字段进入行详情。

## 3. 信息架构

```text
公共壳层
├── AI 工作台
├── 数据
│   └── 数据中心
├── 内容
│   ├── 任务管理
│   ├── 内容管理
│   └── 内容资产
├── 分发
│   └── 分发管理
└── 系统
    ├── AI配置器
    └── 网站设置
        ├── 网站与品牌
        ├── 首页与主题
        ├── 表单与线索
        ├── 用户与权限
        ├── 安全与审计
        └── 系统更新
```

左侧导航只承担一级定位。复杂模块使用页面内标签、局部导航、面包屑和关联操作进入，避免在公共侧栏堆放大量子页面。

|---|---:|---|
| AI 工作台 | 1 新增 | AI 对话、任务理解、执行过程、结果确认 |
| 数据中心 | 7 | 运营总览与 6 个分析页面 |
| 任务管理 | 3 | 列表、新建、编辑 |

| 内容资产 | 31 | 知识、关键词、标题、图片、作者、分类、URL 导入 |

现有 83 个公共壳层页面加 1 个 AI 工作台，共 84 个左右分栏页面。登录页和主题生成预览页作为两个独立页面处理。

## 5. 设计系统

### 主题

浅色、精确、偏运营工具。白色固定侧栏、白色工具栏、浅灰工作画布形成三层表面。蓝色只用于当前选中、主操作和关键数据。

### 颜色

| 角色 | 值 |
|---|---|
| 画布 | `#f9fafb` |
| 表面 | `#ffffff` |
| 主文字 | `#111827` |
| 次文字 | `#4b5563` |
| 弱文字 | `#9ca3af` |
| 分隔线 | `#e5e7eb` |
| 主蓝 | `#2563eb` |
| 选中背景 | `#dbeafe` |
| 成功 | `#059669` |
| 警告 | `#d97706` |
| 危险 | `#dc2626` |

### 尺寸

- 侧栏展开 256px，收起 72px。
- 顶部栏 64px。
- 桌面菜单行 36px，移动菜单行 40px。
- 标准内容最大宽度 1280px，AI 聚焦内容最大宽度 768px。
- 桌面内容左右间距 48px，平板 24px，手机 16px。
- 导航圆角 6px，控件和普通卡片 8px，AI 聚焦卡片 16px，标签使用胶囊形。

### 深度

页面依靠背景层级与细分隔线组织。普通卡片使用轻微阴影，菜单和弹窗使用中等阴影。禁止渐变、玻璃模糊、粗侧边强调线和无意义装饰。

        │

公共组件包括页面标题、指标、筛选栏、表格、分页、标签页、状态标签、表单字段、上传、空状态、错误状态、权限状态、确认弹窗、抽屉和 Toast。

## 7. 实施阶段

### 阶段一：公共壳层

建立共享侧栏、顶部栏、账户区、路由权限映射、设计变量和响应式行为。完成后，现有 72 个共享布局的 Blade 模板立即获得统一左右分栏。

### 阶段二：核心页面母版

把本次三个试点结果整理为运营首页、密集列表和复杂设置母版，再补齐表单、详情、分析、审核、卡片、向导和异常母版。每个母版完成后都能独立上线。

### 阶段三：高频业务

依次迁移数据中心 7 页、任务和内容管理 11 页。该阶段结束后，日常主要运营路径完整可用。

### 阶段四：内容资产和分发

迁移内容资产 31 页、分发管理 13 页，重点处理宽表格、上传、异步状态、批量操作和删除影响确认。

### 阶段五：配置和系统

迁移 AI 配置器 5 页、网站设置 16 页，把用户管理、API Token、安全、审计和更新入口合并到网站设置上下文。

### 阶段六：特殊页面和完整验收

完成登录、主题预览、403、404、500、加载、空数据、失败和无权限状态。执行桌面、平板、手机、中文、英文和权限回归。

## 8. 验证矩阵

- 视口：1440、1280、1024、768、375、320。
- 身份：普通管理员、超级管理员、登录失效。
- 状态：正常、加载、空数据、错误、无权限、部分数据缺失。
- 操作：筛选、分页、创建、编辑、保存失败、删除确认、导出、上传、轮询和返回。
- 布局：侧栏固定、菜单独立滚动、收起、移动抽屉、表格横向滚动、长中文和英文。
- 可访问性：跳到正文、键盘焦点、图标按钮标签、弹窗焦点锁定、降低动画偏好。
- 技术：Laravel 路由回归、Blade 渲染、翻译键检查、Vite 构建、相关 Feature 测试。

## 9. 发布和回退

改造只触及视图、公共前端资源和必要的页面组件，不修改数据库结构和业务接口。每个阶段独立合并，保留原布局文件一个发布周期，并通过单一配置开关控制新旧壳层。发现严重视觉或交互回归时，可立即切回旧壳层，不需要回滚数据。

本方案假设现有控制器提供的数据结构和表单契约保持稳定。如果全量实施期间同时大改业务字段，页面迁移成本会上升，因此业务字段变更应单独排期并先更新页面清单。
