# URL 变更风险管控：升级与运维

本次升级保护主站规则、第一方托管站规则、既有分类 URL 标识，以及会改变当前链接的文章分类调整。现有规则、分类标识和 `/admin` 配置保持原值，升级不会自动切换地址。

## 管理流程

1. 超级管理员从“自定义文章链接”、分类编辑或文章编辑发起“检查影响”。先保存标题、正文等其他编辑内容。
2. 检查在后台分批执行。报告区分关联文章、公开文章、站点地址、未来发布/恢复的地址和已同步记录。
3. 下载迁移清单，核对新旧地址、跨站点影响及历史规则数量。
4. 在页面正中弹窗输入完整确认语。凭据绑定发起管理员、认证版本、作用范围和报告摘要，检查完成后有效期为 15 分钟。
5. 短事务应用新规则或标识。旧地址直接 301 到当前规范地址，查询参数保持原始顺序与编码。
6. 后台继续刷新 Sitemap 与第一方托管地址记录。显示“地址已生效，正在刷新”期间请保持规则稳定；全部刷新完成后显示“变更已完成”。

正文、访问次数等变动不使报告失效。新增/发布/恢复文章、URL 字段、站点归属等变化会使相关报告过期，需要重新检查。数据持续写入的繁忙站点可能多次过期，应选择稳定的维护时段。

普通管理员可以编辑分类显示名称、描述等非 URL 字段。API、CLI、自动化对存量受保护字段的修改：普通管理员收到 403；超级管理员收到 409 `url_change_confirmation_required`，需转到后台确认。请求同时含正文等其他字段时，整次拒绝，不部分保存。直接 SQL 属于人工运维边界，网页权限和弹窗不能约束数据库管理员。

## 升级条件

- 先备份数据库与私有存储，安排维护窗口。新增索引和触发器迁移在升级清单中标记为离线迁移。
- 新增三张表：`category_slug_histories`、`url_change_requests`、`url_change_scope_states`；另增加 URL 数据版本触发器及文章分类游标索引。
- 校验 `deployment/upgrade-plan.json` 后，按现有受管升级流程执行迁移、切换应用与生产资源、更新路由缓存，并让队列 Worker 使用新代码。
- 队列必须采用实际异步驱动，并消费默认队列；`sync` 和 `null` 驱动会阻止发起检查。调度器需每分钟正常运行，负责中断恢复及报告清理。
- PHP Worker 必须能读写私有 local 磁盘；多个应用/队列节点需共享同一私有报告存储和支持原子锁的缓存，不能使用各节点互不相通的临时磁盘或 array 缓存。
- 保留现有 `ADMIN_BASE_PATH`。本次路由使用配置的前缀，不要求改成其他后台地址。

本轮仅修改代码并使用隔离环境验证，没有执行本地业务库迁移、业务容器重建、生产部署或远端站自动同步。

## 大站点的资源保护

| 环节 | 当前限制与处理 |
| --- | --- |
| 文章检查 | 主键游标，每批至多 500 篇，仅选 URL/摘要字段，不加载正文 |
| 历史标识检查 | 每批至多 100 条；巨大单篇历史继续游标处理 |
| 作业调度 | 同一范围串行，单批任务超时 60 秒；正常续批延迟 1 秒，释放执行资源 |
| 新增地址归属 | 索引定位，最多 500 候选及 2 秒计算预算；复杂重叠模板无法证明安全时拒绝写入并说明原因 |
| 迁移文件 | 私有存储，单请求累计 2 GiB，写入后至少保留 1 GiB 可用空间；不足时检查失败，原规则不变 |
| 报告显示/下载 | 页面每次 20 条；CSV 每片至多 100,000 条，防表格公式执行，按快照流式读取 |
| 报告保留 | 终态后 24 小时；过期下载返回不可用，调度器清理文件，保留变更记录 |
| 托管 `remote_url` | 每批至多 200 条，锁定渠道并核对数据版本，保存刷新游标；不外呼独立 Agent、WordPress 或 HTTP API |
| Sitemap | 按 500 个 ID 建立分片边界，分片流式输出，完整构建后原子切换 manifest；构建时可继续使用上一份完整 manifest |

500,000 篇文章、2,510,000 条旧标识的实测检查共需 26,105 个步骤。连续执行的计算耗时约 8 分钟；真实队列逐批 1 秒节流，额外等待约 7.25 小时，另受队列排队影响。界面已提示大历史集合可能需要数小时。应在低峰期提前发起检查，检查期间现有地址继续服务。

上述 2 秒归属预算限制应用层计算；数据库慢查询或锁等待还需部署环境的数据库超时、监控和容量规划配合。高度重叠的混合令牌模板可能触发保护性拒绝，推荐使用独立分类层与完整 slug/ID 层。

## 故障处理

- **检查失败 / 报告失效**：当前地址未变。按提示处理冲突、磁盘、权限或数据变动后重新检查。
- **检查长时间不推进**：检查队列与调度器是否运行、Worker 是否消费默认队列、私有存储和缓存是否共享。恢复器会重派超过 2 分钟未更新的活动任务；锁避免同一变更并行处理。
- **已生效但刷新失败**：新地址已生效，后台从游标继续刷新。排查 Worker、数据库及磁盘后恢复队列；不要再次切换规则来重试刷新。
- **托管站被归档/移除**：报告列出跳过刷新站点并释放本次占用；该站重新上线前需单独核对地址。
- **第一次构建大站 Sitemap 尚未完成**：没有旧完整 manifest 时可能临时返回 503 和 `Retry-After: 60`，Worker 完成后恢复；请在上线验收时预热并确认。
- **需要切回旧值**：仍走同一检查与确认流程，产生新版本并保留历史。普通代码回退不能删除分类历史表；完整旧版本回退需要另外评估兼容性。
- **外部缓存**：已经发出的 A→B 301 可能被缓存，快速反向切换可能产生客户端循环。先核对已有缓存有效期，处理可控缓存后再安排切回。

结构化配置统计检查各站点首页模块、图片广告、文字广告的独立 URL 字段，按配置项计数；同一项包含多个旧链接计 1 项。正文、富文本嵌入链接和第三方配置需另查，报告数量不代表访问量、收录数或外链次数。

## 实现约束

- 预检必须使用前台相同的请求路径限制，并验证生成地址能定位回原文章。编码后的路径最多 2,048 字节；分类与文章标识混在同一段时须逐条核验，独立路径段可保留批量校验优化。
- 文章同时调整任务或分类时，按文章行、原/目标任务行、原/目标分类行、URL 版本范围的顺序加锁；同类资源按 ID 或范围键排序。分类改名在版本范围前锁定分类行，避免数据库触发器与外键检查形成循环等待。
- 修改后台入口前，检查主站和全部第一方托管站的当前及历史规则，同时保护历史分类标识。归档托管站的规则继续保留兼容保护。
- 刷新已同步的第一方托管地址记录时包含回收站文章，保证恢复后使用当前规范地址；删除动作记录继续排除，刷新不改变文章的删除状态或发布状态。
