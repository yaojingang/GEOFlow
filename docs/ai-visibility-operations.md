# AI 可见性专题与词云

分析页保留关键词库批量采集、竞品名单管理、后台竞品识别和 Top URL。搜索工作台支持搜索数量、模式、摘要、时间、行业和站点过滤，搜索及付费分析操作仅对超级管理员开放。

## 专题归类

`ai_visibility_topics` 保存专题，关键词经去首尾空白、大小写和空白归一后，以哈希绑定专题。搜索时可以选择专题；历史采样可在结果工作台归类。同一关键词的后续采样会沿用已有绑定，分析页可按专题筛选信源、样本与竞品证据。

升级后如需归类既有采样，先维护专题关键词绑定，再运行：

```bash
php artisan geoflow:ai-visibility:backfill-keyword-hashes
```

命令可重复执行。它只处理真实采样提供商，跳过竞品发现和词云清洗等辅助调用，不会调用模型。

## 词云清洗与费用

打开或刷新分析页只读取已缓存的清洗结果，缓存缺失时立即展示启发式候选词。GET 请求不会调用模型或派发清洗任务。

超级管理员点击“刷新词云清洗”后，以 POST 提交清洗请求。此操作会消耗已绑定系统分析模型的调用额度，沿用调用互斥锁、额度预留、执行前后权限与绑定检查，并写入真实模型调用记录。额度耗尽、模型不可用或绑定在调用期间撤销时，保留启发式结果。

清洗结果按候选词、权重、模型身份、凭据版本和提示词版本缓存。相同签名由共享缓存锁去重，命中缓存不重复计费。成功缓存默认保留 12 小时，失败短暂缓存最多 10 分钟。多实例部署需使用共享缓存。

`GEOFLOW_AI_VISIBILITY_TERM_CLEANUP=false` 可停用词云清洗。候选数量、输出长度、超时和缓存期限沿用 `config/geoflow.php` 的现有清洗配置。清洗使用独立的 `term_cleanup` 调用类型，与 `competitor_detection` 一起排除在可见性 KPI、关键词候选及专题回填之外。

## 信源与竞品证据

信源分布按专题汇总渠道、收录数和权威标记。搜索后的竞品证据解析保留可回溯的来源链接，无法对应来源的条目标为待核实。竞品品牌的后台发现继续使用独立异步流程。页面仅为 HTTP 或 HTTPS 来源提供可点击链接。

先按正式升级流程执行迁移，再进行历史关键词回填。本手册中的命令需由运维在指定实例执行，部署前先完成备份与验证。
