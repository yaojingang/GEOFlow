## 交付范围

- 超级管理员权限、绑定身份/版本的确认凭据、输入式二次确认、API/自动化受保护字段守卫。
- 分类历史标识与删除占用保护，旧分类/文章地址直接 301，原始查询参数保持不变。
- 后台分批检查、去重文章与站点地址统计、私有 CSV、版本过期、重复提交与中断恢复。
- 主站/托管站规则、分类标识和影响链接的文章分类调整均接入居中风险弹窗；中英文、窄屏、键盘和失败状态有验证。
- Sitemap 游标分片及完整 manifest 原子替换，第一方托管 `remote_url` 分批刷新。
- 结构化配置中旧链接的定位计数、10 条以上历史规则的性能提示、报告数据版本展示。

未执行业务数据库迁移、业务容器重建、生产部署、远端 Agent 自动同步、提交或推送。业务 URL 规则及后台路径未调整。其他任务的未提交改动完整保留。

## Review 中修复的问题

1. 取消检查的旧返回入口会丢失目标草稿或留下占用：改为显式取消并恢复目标值，同时阻止已应用任务被取消。
2. Vditor 快捷插入正文未触发普通表单变更事件，可能在跳转检查页时丢稿：增加提交前真实表单快照核对，并处理编辑器初始化换行归一化。
3. API 执行身份读取错误、存量 URL 字段显式空值以及普通分类保存与并发规则确认的竞态：统一守卫、事务内重新锁定范围并复核规则。
4. 后续新增文章/托管归属缺少反向地址占用校验：补齐当前/历史规则的所有权检查。
5. 混合令牌的贪婪拆分、编码 slug、分类值 `0`、迁分类及历史日期修正可漏判旧 URL 冲突：使用受预算限制的路径分割推导，复杂未证明安全的交集拒绝写入。
6. 后台切换规则也可能漏掉迁分类前的地址：相应模式对复用反向检查，完整独立定位段的常见模板保持快捷路径。
7. 托管站归档后的刷新占用、重复确认摘要变化、中断任务恢复及文件配额错误：补齐跳过说明、幂等和可恢复状态。
8. Sitemap 旧完整清单与新文章数量不一致时，旧分片可能提前失效：按对应完整 manifest 的边界服务。
9. 配置旧链接统计只搜索 `/article/` 会漏掉自定义规则及更早分类标识：改为 URL 匹配与归属查询，按配置项去重，排除外域和已采用的新地址。

## 第二轮 Review（后续复核）

本次针对当前未提交实现进行了权限、架构、地址归属及四类异常操作序列复核，补充修复四类问题：

1. **预检通过后地址仍可能无法访问**：复合令牌可能拆分出错误 slug，旧 Unicode 分类与长 slug 组合可能超过前台 2,048 字节限制。同长度模板的复合展示段也可能解析出无效值。预检与新增文章检查复用前台路径限制，逐条证明地址能定位回原文章；仅单令牌路径段、相同令牌集合和模板字节长度可复用校验。
2. **并发保存可能失败**：独立 PostgreSQL 测试分别复现源分类改名、目标分类改名、目标任务更新与文章修改形成的死锁。统一文章、任务、分类和版本范围的加锁顺序，补齐两侧关联行与范围锁。
3. **后台入口修改漏查旧地址和托管站**：兼容检查加入历史分类标识及全部第一方托管站的当前/历史规则，包含归档站，冲突时保持后台入口原值。
4. **回收站文章恢复后托管记录仍为旧地址**：新旧两个刷新作业都包含软删除文章的必要元数据，分类筛选也包含回收站；继续排除删除动作记录，不改变文章状态。

新增 32 个回归用例（29 个功能用例、3 个 PostgreSQL 并发用例），同时包含错误复现与合法输入对照。错误用例在修复前实际失败，修复后通过。此次没有改变公共 URL 匹配规则、自动切换站点规则或修改业务库。

后文的 10 万、30 万、50 万及 251 万历史标识数据属于上一轮实施验证；本次补测结果单独记录，避免混用不同数据规模和测试环境的结论。

- 隔离副本排除了 Git 忽略的本地法律主题及其配套 PHP/JS 测试，保留仓库测试与本轮测试；共享工作区中的其他在途功能仍包含在集成回归中。
- PostgreSQL 压力数据通过 SQL 批量生成，执行真实迁移、服务、查询、报告和刷新路径。文章正文约 1 KiB；检查不读取正文。
- 主站前台探针走 Laravel HTTP 内核，预热后基线 20 次、并行加载 100 次，间隔 100 毫秒。数据统计/HTTP 内核测试不等同于公网吞吐量、多用户 RPS 或冷缓存生产容量认证。

- 内存增量指 PHP Worker 的峰值增量，不包含 PostgreSQL 进程或 Docker Desktop 的总内存。

## 容量结论与限制

分批检查的时间、内存和应用延迟符合本轮已测预算。50 万文章与 251 万历史标识可以完成检查，历史集合大小不会被一次装入内存。

**前台延迟增幅目标未全部达到：10 万档为 +37.9%，最终 50 万复跑为 +20.7%，均超过 20% 目标。** 原有前台文章推荐/排序查询、宿主机竞争和缓存条件会影响结果，不能据此宣称 50 万规模在任何部署上都已通过容量验收。

部署建议：低峰期操作，单范围串行检查，保留队列节流；使用独立异步 Worker、共享持久缓存与报告磁盘；监控 HTTP p95、数据库慢查询/锁等待、队列积压及磁盘空间。需要生产容量承诺时，应在目标硬件上补做真实 HTTP、多用户并发、冷热缓存及持续发布负载测试。

大量历史数据的真实队列时间可达数小时；持续 URL 数据变动可能让报告重复失效。复杂混合模板超过所有权证明预算时会安全拒绝，旧规则保持不变。报告清理依赖调度器；Sitemap 没有任何旧完整 manifest 时，首次后台构建期间可能短暂返回 503。

升级与回退步骤见 [运维说明](../deployment/URL_CHANGE_RISK_CONTROL.md)。
