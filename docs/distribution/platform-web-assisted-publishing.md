# 平台网页人工辅助发布

## 配置渠道

超级管理员在“分发渠道 > 新建”选择“平台网页（人工辅助发布）”，选择头条号、搜狐号或网易号，并绑定同平台的启用账号。账号与人设在人工发布工作台的设置中维护，属于实例共享的管理资源。渠道创建管理员需要保持启用的超级管理员身份。

编辑器地址留空时使用平台默认地址。覆盖地址必须位于所选平台的 HTTPS 编辑路径。已经产生分发记录的渠道保持平台身份固定；变更平台请新建渠道。编辑配置时仍受渠道删除状态和运行中操作保护。

## 完成人工发布

1. 将渠道关联到内容任务，按任务的现有发布策略生成分发记录。
2. 分发创建一个“待执行”的人工发布工作单，分发记录显示 `awaiting_extension`。
3. 指派管理员在 Chrome 运营助手领取，确认当前登录的平台账号，打开目标编辑器。
4. 复制工作单标题与正文，人工粘贴、检查和发布。启用“附加来源链接”时，复制正文会附带来源网址。
5. 在扩展提交发布 URL 和结果回执。工单完成后，分发记录收敛为 `synced`。

这三个平台使用人工复制与回执流程。自动填充目前由现有知乎回答适配器提供。更新、删除和站点内容刷新请在目标平台人工处理，渠道不会将这些操作标记为已同步。

标题、正文和来源路径沿用分发时保存的文章载荷。之后编辑源文章不会改写待执行工单。每个分发记录最多关联一个工作单。失败或结果不明后，超级管理员须在目标平台核实未发布，再到工作单详情输入“确认未发布”，提交“确认未发布并重试”。系统使用当前有效的源文章授权生成原工作单的新修订，保留历次领取、回执和确认人记录。旧领取和旧回执无法用于新修订。

## 结果不明与删除

收到 `outcome_unknown` 后，先在目标平台核实发布结果。确认已发布时补录 URL；确认未发布后，由超级管理员在工单详情输入“确认未发布”，提交“确认未发布并重试”重新授权。系统阻止同文章、同平台的已完成、待回执和未知结果重复投递。

删除渠道或任务会取消尚未领取的工单。已经领取的工单保留为结果待核验，并清理领取凭据、推进版本，旧版本回执将被拒绝。已保存的完成 URL 和执行凭证保留用于人工核验。

## 回执对账

回执先持久保存，事务提交后再桥接分发记录。桥接失败会记录告警，运维可运行：

```bash
php artisan geoflow:reconcile-platform-web --limit=100
```

调度器每分钟运行此命令，并防止重叠执行。每轮最多处理 500 个工单，默认 100 个；只扫描尚未应用的新终态修订，重复运行不会重复记日志。恢复校验阶段会暂停命令，实例恢复就绪后继续。

命令只更新本地状态，不会重新向平台发布。平台发布事实优先保存在原工单中。渠道和任务删除不会通过迟到回执重新创建分发记录。

## 数据迁移

部署本功能时，通过项目的正式迁移流程建立人工发布关联列及唯一约束。此约束适用于允许多个空关联的普通人工工单。升级前备份数据库；对已有实验分支数据，先核查同一个 `source_distribution_id` 是否出现重复工单，保留可追溯记录后再执行迁移。

## 分发快照与领取授权

关联 `source_distribution_id` 的工单由分发快照管理。通用工单编辑入口拒绝修改来源文章、平台、账号、人设、内容、目标 URL 和浏览器载荷；通用“重开 / 待执行”操作也不可重新授权。普通独立人工工单沿用原编辑流程。

领取按渠道、任务、文章、分发、工单的顺序加锁，再核对分发状态、主线工作流 fence、不可变文章载荷和工单摘要。人工暂缓、取消分发、任务停止或绑定变化都会阻止旧领取。操作员须通过源分发的受控重新入队更新尚未执行的快照；已领取、结果不明或已有执行凭证的工单需要先人工核实，系统不会自动重新发布。

维护时应将新执行授权与外部事实记录分开处理。回执记录允许保存已发生的真实结果，晚到完成事实可补充远端身份；终止分发保持原状态及 fence，禁止迟到回执重新激活。

### 失败后的人工重新授权

普通重新入队和定时任务会保留已领取记录的重发保护。`failed` 回执同样需要人工核实；`outcome_unknown` 默认等待核实。超级管理员打开工作单详情，确认平台上没有本次发布后，输入“确认未发布”提交表单。该表单复用源分发的重试动作，并携带当前工单修订号。修订已变化、已有完成事实、账号或管理员停用、渠道删除、任务停止、文章暂缓或当前质检不通过时，系统拒绝重新授权。恢复任务及文章的合法发布状态后可重新核实并提交。

开发契约：重新授权沿渠道 → 任务 → 文章 → 分发 → 工单加锁，先复核原不可变绑定，再通过主线入队检查刷新当前载荷与工作流 fence。确认仅授权原工单的一个新修订，历次回执与该次授权的文章、发布载荷快照保存在原 `execution_receipt.previous_attempts`，领取与确认审计沿用工单转换记录。浏览器回执仍按领取修订校验，并保留晚到的真实外部事实。自动发布器没有人工确认能力；已完成事实始终阻止重发。


同文章、同平台的去重同时检查工单状态、领取转换与执行回执。已经领取后收到失败回执，或把未知结果标记为失败，都会保留执行历史；更换同平台渠道仍须在原工单核实并重新授权。需要重试时，先恢复原渠道与任务的有效关联。尚未领取、没有回执或执行历史的取消工单可按原规则重新入队。

复制正文从分发保存的 `content_html` 提取纯文本，Markdown 源快照保留。缺少 HTML 的历史快照使用与正文页面相同的可信渲染器。标题层级、强调、链接及图片语法不会作为格式标记复制，代码中的字面文本保留。
