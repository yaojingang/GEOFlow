# 文章工作流运行与恢复说明

适用范围：包含文章发布意图、工作流版本和 `score-release-1` 评分策略的版本。生产部署和历史文章恢复应分别确认操作范围。

## 本轮升级内容

| 场景 | 升级后的行为 |
| --- | --- |
| 批量操作 | 首次提交读取当前选择；空选择禁用执行；逐篇返回成功、无需变更、阻止、冲突或失败 |
| 任务自动发布 | 统一读取当前任务设置，符合审核、风险及质量条件后，按发布间隔执行 |
| 人工操作与迟到回调 | 草稿保留、拒绝、暂停和内容修改更新工作流版本，旧回调不能覆盖当前意图 |
| AI 按分数放行 | 普通问题计入扣分，达到任务阈值即可通过；严重风险和检查不完整仍明确阻止 |
| 发布与分发 | 本地发布和远端交付分别记录；事务后交接、有限重试及幂等保护防止漏发和重复发送 |
| 任务设置 | 默认、固定、随机分类分别执行；SEO 关键词与摘要开关各自生效 |
| 运行诊断 | 显示具体阻止原因、重试时间、质检失败阶段和交接状态；历史恢复先生成审阅清单 |

人工审核与 AI 质检的基础组合：

| 人工审核 | AI 质检 | 自动发布前置条件 |
| --- | --- | --- |
| 关闭 | 关闭 | 基础风险通过、有效发布安排、任务运行及间隔满足 |
| 关闭 | 开启 | 基础条件满足，当前完整质检报告达到通过分数且无硬性阻止 |
| 开启 | 关闭 | 基础条件满足，当前内容已获人工批准 |
| 开启 | 开启 | 基础条件满足，当前内容人工批准与 AI 质检均通过 |

开启自动优化时，还需满足选择的优化目标；抽样结果须满足抽样放行及覆盖条件。单独的高分不会解除人工保留、拒绝或暂停。

提交前复核补充了金额单位精确换算、独立事实扣分上限、已发布内容修改权限、关闭 AI 后旧分发继续执行、开启人工审核后阻止未获批准的分发，以及旧人工放行请求的业务反馈。对应回归位于评分校验、API 文章风险工作流、分发风险工作流和后台 AI 质检测试中。

## 当前规则

- 人工审核与 AI 质检独立设置。关闭 AI 后使用当前任务策略；基础风险、人工审核、发布安排和间隔仍然有效。
- `scheduled` 随任务间隔发布；`immediate` 表示明确立即发布请求；`hold` 保留草稿/私有并停止发布；`none` 表示没有待执行发布请求。
- “审核通过”记录当前内容的人工批准。已有有效立即发布请求时，批准后继续检查剩余条件；保留文章的审核通过不会新增发布请求。审核备注不能充当风险放行理由。
- 暂停增加任务自动执行版本，撤销旧立即发布请求。恢复承接仍有效的 scheduled 工作、尚未发送的分发、已获安全重试授权的分发和可恢复交接。安全重试保留原尝试次数及等待时间；人工保留、拒绝、旧内容版本和任务已移除的渠道继续停止。
- AI 采用最终分数放行：普通质量问题、证据不足及不确定性计入扣分，达到任务通过分数即可通过。严重风险、证据提示注入、涉及关键事实的严重知识冲突及检查不完整保留明确拦截原因；人工审核、发布安排、暂停、优化目标和发布间隔继续有效。抽样必须覆盖必检声明与前中后区域，且系统开启抽样放行。
- 评分策略版本为 `score-release-1`。证据覆盖部分内容扣 5 分、不足扣 10 分；与知识一致性/证据维度已有扣分取剩余差额，避免重复扣分。独立不确定项按高/中/低扣 6/3/1 分，相同声明去重。具体问题沿用对应 V1/V2 维度权重和扣分表。列表同时显示得分、结论与通过分数，详情显示拦截原因及补充扣分。
- 升级前的报告保留用于追溯；算法指纹更新后需重新质检，不能用旧报告直接放行。当前策略内仅调整阈值时可安全重算完整报告。暂停和人工保留状态不会因升级或重算解除。
- 本地发布与远端成功分别统计。仅分发模式在本地保持 private，远端状态查看分发记录。

## 技术故障及交接

AI 技术重试只接受明确白名单：入队失败、模型/提供商超时、限流、网关错误、熔断和 worker 中断。最多额外两次，等待至少 60 秒、300 秒，同时尊重 Retry-After、额度/熔断检查。鉴权、额度不足、未知错误及内容结论不进入该自动重试链。暂停恢复保留原尝试次数。

质检已完成后的工作流应用失败保留报告，由已有对账入口恢复。发布事务同时写入 `distribution_logs` 的 `publication.delivery_handoff`，提交后安排渠道任务。交接失败有限重试；过期租约可恢复；旧租约不能覆盖新结果。最多三次交接尝试，耗尽后需要检查渠道并明确重试发布。普通回调不会重复安排已完成交接。用户明确再次点击发布时，重新核对当前渠道；渠道层根据副本身份和载荷去重。删除远端副本后，同一文章与渠道的全部发布、更新、删除记录共用递增副本版本，新副本使用新的幂等键。

周期收敛继续使用 `geoflow:converge-ai-quality`，即使任务关闭 AI，也会恢复待处理的分发交接和已落库但未成功提交队列的分发。队列提交失败最多自动尝试三次，间隔至少 60 秒、300 秒；耗尽后显示 `distribution_queue_retry_exhausted`。恢复服务分别执行，一项故障不会跳过其他服务。该命令会推进工作，操作生产时应遵循生产授权范围。

包含远端写入的数据库事务只执行一次。远端已返回成功、本地保存失败时，系统尽量保留远端 ID，并将分发标记为 `outcome_unknown`。同一文章和渠道的入队、立即更新及立即删除都会等待对账；按现有渠道对账流程核查远端结果，避免盲目再次创建。发布器内部辅助信息保存失败同样保留已收到的响应。

自动优化允许当前有效的发布意图重新启动被人工动作或暂停作废的运行，重新生成候选；旧候选继续失效。预算耗尽、无改善、治理阻止等业务终态不会因重复完成回调重开预算。私有文章已有立即发布请求时，对账和执行使用相同资格规则。

## 历史恢复

迁移为历史未发布文章保守设置 hold，不推定其过去的人工意图。恢复工具默认只预览，单份清单最多 500 篇：

```bash
php artisan geoflow:reconcile-article-workflow --task=123 --limit=100 --manifest=/absolute/path/workflow-preview.json
```

也可重复提供 `--article=456` 精确选择文章。路径应为新文件；已有文件不会被预览覆盖。

逐篇检查 `before`、`proposed_review_status`、`blocking_reasons` 和 `excluded_reason`。确认的条目才设置 `reviewed: true`；确认恢复某篇 hold 文章的任务自动发布安排，才设置 `release_hold: true`。保持 manifest ID、文章 ID 和 before 快照不变。未知人工意图、拒绝、已发布文章保留原状态。

取得历史恢复授权后，使用已审阅清单：

```bash
php artisan geoflow:reconcile-article-workflow --apply --manifest=/absolute/path/workflow-preview.json
```

应用逐篇事务处理，核对版本、内容、任务策略及文章级质检配置。升级前生成的旧清单应重新预览；清单生成后修改文章质检覆盖方式，会返回 `preview_changed`。清单生成后的修改返回 conflict；未确认的条目返回 blocked。每篇成功操作写审计。相同清单再次应用跳过成功条目，并可恢复之前失败的条目。该命令不批准内容、不调用模型、不直接发布文章；释放 hold 后，后续发布仍由任务运行状态和全部门禁决定。

## 发布与回退准备

1. 备份数据库；记录当前代码版本、队列与调度运行状态，检查两个新增迁移及升级清单。
2. 进入维护窗口，停止调度并让旧 worker 停止取新任务、完成或退出正在执行的任务，避免新旧状态规则混跑。
3. 应用新增字段/索引迁移，部署匹配代码及构建资源，重启队列，再恢复调度。检查任务设置、一个免审免 AI 新任务和批量操作。
4. 保留历史清单预览，分别确认生产恢复范围。出现问题先暂停自动执行；回退代码时保留新增数据列及审计，重新核对旧代码对发布意图的支持。直接回退迁移会丢失意图与版本，不能当作普通代码回退步骤。

## 可观测性

文章响应/详情提供工作流版本、有效配置、发布意图、阻止原因、重试时间、质检失败阶段及分发交接状态。任务列表和实时轮询只做汇总；单任务监控详情按需精确计算全部未发布文章，`task_progress.diagnostics_loaded` 标识诊断是否加载。未加载时省略 ready_articles，避免用零冒充计算结果。

排查具体线上案例时，应核对原始异常、模型请求、队列记录、当次实际召回证据及治理状态。模拟测试不能替代运行时证据。
