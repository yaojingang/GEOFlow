# GEOFlow Chrome 运营助手运行手册

## 能力边界

Chrome 运营助手从人工发布工作台读取已分配工作单，使用用户当前的浏览器登录状态打开目标页面并填充草稿。最终发布操作由用户完成。服务端不接收平台 Cookie、密码或登录 Token。

首个页面适配器支持知乎问题页的纯文字回答。头条号、搜狐号和网易号使用人工辅助模式，包括领取、打开目标页、复制标题、复制正文和回传结果；发布前由操作员核对平台账号。渠道配置、未知结果与回执对账见[平台网页人工辅助发布](distribution/platform-web-assisted-publishing.md)。其他平台继续使用通用模式。

浏览器队列只展示已分配、已生成浏览器载荷且带目标 URL 的工作单。一个 Chrome Profile 连接一个 GEOFlow 实例；需要同时使用多个平台账号时，为每个账号建立独立 Chrome Profile。

## 部署

1. 部署应用代码并执行数据库迁移。
2. 确认生产环境使用共享缓存，推荐 Redis，以便设备授权请求在多实例之间可见。
3. 使用 `npm run test:browser-extension` 验证扩展纯逻辑。
4. 使用 `browser-extension/scripts/package.sh` 生成扩展 ZIP。
5. 内部灰度阶段通过 Chrome 的“加载已解压扩展程序”安装。
6. 商店发布前公开 `browser-extension/PRIVACY.md`，准备截图和专用测试账号。

## 配对与撤销

扩展申请的配对码有效期为 10 分钟。管理员必须登录 GEOFlow 并核对配对码后批准。批准后签发的 Token 只有 `browser-operations:read` 和 `browser-operations:execute` 权限。

管理员可以从“账户与权限 > 浏览器连接”撤销自己的连接，超级管理员可以撤销所有连接。修改管理员密码也会撤销该账户的全部 Token。

## 工作单恢复

浏览器领取工作单后每 60 秒发送心跳。心跳中断超过 10 分钟后，负责人应先在目标平台核验是否已经发布：

Chrome 或侧边栏重开后，同一个浏览器连接可以从队列重新打开已领取工作单；扩展会恢复当前正文、执行时间和心跳。连接 Token 已撤销或工作单无法恢复时，再进入人工核验流程。

- 确认未发布：将工作单恢复到“待执行”。
- 已发布且获得 URL：补录为“已完成”。
- 无法判断：标记“结果待核验”，完成后续人工确认。

系统不会自动重新派发失联工作单。

## 故障定位

- `upgrade_required`：扩展协议版本与服务端不兼容，升级扩展。
- `account_mismatch`：当前平台账号与工作单 `profile_url` 不一致。
- `editor_not_found`：目标页面 DOM 已变化，停用该适配器并使用通用模式。
- `claim_owned_by_another_client`：工作单由另一个浏览器 Token 持有。
- `outcome_unknown`：发布结果无法安全确认，需要人工核验。

## 紧急停用

撤销浏览器 Token 并停止扩展分发。现有人工发布工作台不依赖扩展，可以继续完成工作单。已经保存的执行凭证和审计记录应保留用于核验。
