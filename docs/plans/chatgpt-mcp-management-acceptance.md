## 1. 当前状态与执行规则

维护者已批准文档方案进入实施准备。本清单共有 80 项后续运行验收规格，A01 至 A80 当前全部为 NOT_RUN。PR#148 仅交付文档，业务 MCP HTTP 端点与 ChatGPT 运营接入仍待实现；未执行数据库迁移或生产操作。文档一致性检查、仓库 CI 和未来 MCP 运行验收分别报告，已有 REST 测试不能代替这些用例。

保留原 A01 至 A48 的验收目的，按原生架构修订凭据、回环 HTTP 与独立服务假设；新增 A49 至 A80 覆盖身份共存、实例部署、统计、原生事务与真实客户端。原生路径不再要求第二套 Core Token，A10 及 A35 分别验证凭据隔离和旧 REST 兼容。

测试环境必须无真实客户数据，使用确定性数据、模拟供应商、受限测试授权和至少两个管理员、两个独立实例。即使演示只连接一个实例，也要测试另一实例和未授权主体的拒绝路径。

每次运行记录：用例 ID、GEOFlow 提交、组件锁定版本、MCP 协议和管理契约版本、插件摘要、客户端/模型/账号及工作区策略、时间与时区、配置、输入、预期、实际结果、脱敏资源与请求 ID、证据位置、执行者。结论只使用 PASS、FAIL、BLOCKED、NOT_RUN；BLOCKED 不能当作通过。

不适用能力必须记录原因并保持关闭，例如未发行 refresh token 时不宣称已验证轮换。未经完整资源授权测试，界面只展示已声明的整实例范围。并发与查询一致性使用实际支持的生产数据库验证；本仓库已有 PostgreSQL 专项门禁，不能仅依赖 SQLite 测试。

### 2.1 D01+D02 最小读取交接

开发边界和步骤见[RFC 第 18.1 节](chatgpt-mcp-management-rfc.md#181-d01d02-首个可交接读取闭环)：先交付身份/grant、可信共享执行上下文、连接撤销页面及 get_connection_status、list_articles、get_article 三个只读工具。测试简称 instance/articles.list/articles.get 不表示现有管理注册表已有这些操作。其他 D02 投影继续按完整 P0 验收，不因此增加草稿、生成、发布或插件实现。

隔离 fixture 包含管理员 A/B、实例 A/B 及跨实例相同数字 ID 的可辨识文章。A 在实例 A 登录并同意最小只读 grant 后读取实例、列表及详情；尚无文章读取 grant 的 B 使用自身令牌、实例 B 令牌访问实例 A 同 ID 时拒绝，伪造 admin_id/grant_id 参数也拒绝；合法 B 仅能读取自己已同意范围。撤销 A 的 grant 后，用旧 access 读取和旧 refresh 换取令牌均拒绝。未发行 refresh 时记录该子场景 BLOCKED 和关闭能力，不能宣称完整撤销链通过。全程不启动付费采集、质检、生成或发布。

首包执行 A01 至 A10、A13、A14、A17、A20、A41、A45、A47、A49 至 A63、A66、A68、A77、A80 的相关断言，并在报告列出实际子场景。A58 必须有数据库/队列前后断言；A02/A03/A55/A56 记录 metadata 及授权链；A08/A09/A51/A57 记录主体/实例拒绝；A41/A68 记录撤销结果。最小闭环通过后，完整 P0 仍需其余适用项。

证据至少包含提交、组件/协议/契约版本，脱敏 instance/admin/grant 和请求关联 ID，metadata/工具 schema 摘要、客户端与工作区配置、字段白名单、预期与实际错误、撤销时间及旧 access/refresh 拒绝记录。不得记录令牌明文。上述交接全部待实施，当前仍为 NOT_RUN。

## 10. 与现有 CI 衔接

当前[CI 配置](../../.github/workflows/ci.yml)包含 PHP 格式与测试、管理操作/路由覆盖、Skill 测试、CLI 验证、前端构建与测试、依赖审计及 PostgreSQL 专项。实现 PR 应复用并增加本期测试，不改变其他门禁的语义。CI 中的成功只能覆盖实际执行的项目。

业务 MCP HTTP 入口及工具、OAuth/Principal/Grant、共享可信上下文及数据投影均待实现；已有 Boost 开发 MCP 另属开发工具。后续草稿并发优先复用 workflow_version 并补齐写入口；收据优先扩展现有 ManagementOperationService/ManagementOperation，另验计划及派发恢复。预算、任务快照、日志聚合、代理与子目录仍需专项验收。数据库迁移应验证全新安装、已有数据升级、回滚保护及备份恢复。

实际 ChatGPT 验收需保留脱敏输入、工具选择、输出、授权/确认行为、时间与版本；API Playground 或 Inspector 成功不能替代目标账号与工作区实测。按[官方接入说明](https://developers.openai.com/plugins/deploy/connect-chatgpt)创建自定义 MCP 插件、安装并@调用，公开 HTTPS 与开发 Secure MCP Tunnel 分别记录，公开目录发布另行验收。套餐、模型、工作区权限及安全策略逐个记录，遇到不支持组合保持对应功能关闭。
