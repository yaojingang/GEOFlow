**GEOFlow 友情链接管理最终方案**

日期：2026-09-13。版本：V2。状态：已确认并完成实现与测试，改动保留在当前工作区。

执行范围为实现与测试，已完成后台编辑、主站首页展示、主题接入和验收。未提交、推送、合并 PR 或部署，未录入真实友情链接。下文保留已确认的设计约定，实施结果见第 12 节。

**1. 推荐结论**

在「后台管理 → 网站设置 → 运营管理」增加「友情链接」入口和独立保存区。管理员维护名称、网址、排序、显示状态、打开方式和链接关系；已启用的链接显示在主站首页底部、版权信息上方。

首期作为一个完整迭代交付，包含后台管理、主站展示、仓库内全部主题接入、新主题生成的默认接入，以及主题包和并发保存验收。修订后预计 2 至 3 个开发工作日，主要工作量在主题兼容与回归验证。估算以现有网站设置与首页链路可正常运行、未追加存量自定义主题改造为前提。

最小实现是沿用现有 `site_settings` 键值表，保存一个友情链接 JSON 配置，配合可增减行的表单和公共展示组件。最终方案在此基础上补充旧页面保存冲突保护，并从数据库直接读取首页需要的这一条配置。新增数据库表、第三方依赖、环境变量、外部服务和定时任务均为 0。

方案假设：主站由管理员人工维护少量链接，本期总容量为 50 条，包含停用记录。这个上限是产品容量选择。若后续需要大量链接、多人频繁协作、逐条审批或定时检查，应在那个迭代引入独立数据表和逐条记录操作；本期已经防止旧页面静默覆盖新设置。

**2. 调研结论与机制**

| 调研结果 | 本期设计决定 |
| --- | --- |
| WordPress 的链接记录围绕名称、网址、可见性、打开目标、链接关系组织；其插入实现也包含更新和缓存清理 | 采用人工维护、启停、排序与保存后刷新展示的基本机制，保留本项目自己的设置存储方式。[WordPress 实现](https://developer.wordpress.org/reference/functions/wp_insert_link/) |
| Google 通常通过具有 `href` 的 HTML 链接提取目标地址，链接文本应简洁并能说明目标 | 首页服务端直接输出文字链接，点击直达目标地址，使用站点名称作为链接文字。[链接实践](https://developers.google.com/search/docs/crawling-indexing/links-crawlable) |
| 普通链接无需特殊 SEO 关系标记；付费或赞助链接应标记 `sponsored`；`nofollow` 用于相应的受限关联场景 | 默认「普通链接」，高级设置提供 `nofollow` 与「广告／赞助」选项。普通链接不生成 `rel="dofollow"`。[出站链接标记](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links) |
| Google 将以操纵排名为目的的过度交换、自动建链等列为链接垃圾行为 | 功能定位为展示相关网站和合作关系，运营时由管理员筛选相关、可信网站。SEO 排名或 AI 引用变化不作为本功能的验收指标。[链接垃圾政策](https://developers.google.com/search/docs/essentials/spam-policies#link-spam) |

本站新增链接，只会改变本站的展示和出站链接。对方网站的回链需要对方维护；本期无需以检测到回链作为展示前提。

上述搜索机制依据 Google 官方资料，不外推为其他搜索引擎或 AI 产品的收益保证。

**4. 后台交互**

网站设置的运营管理分组增加「友情链接」卡片，显示「共 X 条，启用 Y 条」。点击后展开并定位到友情链接编辑区，页面样式沿用当前设置页，增加链接图标，不另建一套导航或视觉风格。

编辑区包含「首页显示友情链接」总开关、可增减行的编辑列表、「添加链接」和「保存友情链接」。所有编辑在点击保存后一起生效。删除先移除待保存行，保存前可撤销；停用保留记录，便于恢复。保存过程中禁用重复提交；校验失败保留输入并定位出错行。编辑区使用独立的 `friend_links` 错误集合，返回路径固定定位到 `#site-settings-friend-links` 并展开该区域。

未保存时显示「有未保存的修改」。离开页面、刷新或提交同页其他设置表单前提醒用户；提交友情链接自身时取消这项离开提醒。该提醒只保护当前表单，不改动其他设置的保存逻辑。

| 字段 | 规则与默认值 |
| --- | --- |
| 网站名称 | 必填，去除首尾空白，最多 80 个字符；作为首页可见文字 |
| 网站网址 | 必填，最多 2048 个字符；完整的 HTTP 或 HTTPS 地址 |
| 排序 | 0 至 9999 的整数，默认 0；值小的靠前，相同值按保存时的行顺序展示 |
| 启用 | 新增时默认开启；停用条目保留在后台 |
| 打开方式 | 默认「新窗口」，可改为「当前窗口」 |
| 链接关系 | 默认「普通」，可选 `nofollow`、广告／赞助；放在行内高级选项中 |

整体显示开关默认开启，初始列表为空；没有启用链接时首页不输出模块。支持保存空列表，清空所有链接无需填写占位数据。

权限、后台登录、CSRF 和操作日志沿用普通网站设置的现有规则。管理员必须处于可登录的有效状态；本期不单独增加权限角色。新保存动作只更新友情链接配置，校验失败时整组保持原值。

首期采用整组保存，并附带打开页面时的配置指纹。两个管理员或两个浏览器标签页同时编辑时，第一个有效保存成功；后续基于旧配置的保存被拒绝，页面保留未保存的内容并提示「配置已被更新，请读取最新配置后重新编辑」。原指纹持续保留，避免再次点击保存就覆盖他人的修改。用户选择读取最新配置时，明确提示当前草稿会被替换。本期不提供强制覆盖按钮或自动合并。

**5. 首页展示**

页面底部的顺序为：现有首页内容 → 页脚内友情链接 → 现有版权与备案信息。

- 标题固定为「友情链接」，跟随站点界面语言提供英文 `Friend Links`。
- 用紧凑的文字列表呈现，继承主题字体、颜色和内容宽度。链接之间留足间距，支持键盘焦点和自然换行；手机上不产生横向滚动。
- 全部启用条目按后台顺序展示，不设置另一套前台截断上限。
- 仅主站正常首页第一页显示。搜索、首页分类筛选、无效分类、第二页及后续页、独立文章页、分类页、关于页和表单页均不显示。
- 带普通来源追踪参数的首页仍可显示；首页判定复用现有搜索、分类和分页条件。
- 总开关关闭、所有条目停用或列表为空时，模块标题、容器和额外间距一并消失。
- 链接直接指向目标网址，HTML 响应中即可读取。首期采用文字展示，图片加载和外站可用性不影响首页渲染。
- 新窗口链接增加 `noopener`；SEO 关系标记由固定选项生成。当前窗口的普通链接无需关系标记；新窗口的普通链接只增加浏览器安全属性。新窗口行为通过可访问文本说明；保留浏览器默认来源策略，不额外添加 `noreferrer`。
- 友情链接目标属于外站，不加入本站 sitemap，不改变首页 canonical 和其他既有 SEO 元数据。

**6. 数据与实现接口**

使用唯一设置键 `friend_links`。值为 JSON 对象，包含总开关 `enabled` 和列表 `links`；每条链接固定包含 `name`、`url`、`sort_order`、`enabled`、`target`、`relationship` 六个字段。`target` 只接受 `_blank`、`_self`；`relationship` 只接受 `regular`、`nofollow`、`sponsored`。

本期新增一个保存路由：`POST <配置化后台前缀>/site-settings/friend-links`，命名为 `admin.site-settings.friend-links.update`。页面入口继续使用现有网站设置 GET 路由。新增路由属于本方案，当前尚不存在。

保存接口使用 HTML 表单响应，成功时重定向回友情链接编辑区；校验失败和配置冲突也返回该区域，保留输入并标记失败。管理日志通过现有中间件记录保存结果，冲突和校验失败不能被记成成功。请求异常及数据库错误按项目现有错误处理方式返回，不显示保存成功。

保存控制器通过现有 `admin_activity_details` 请求属性明确填写成功或失败结果，避免命名错误集合未被默认错误集合检查识别。表单业务字段全部置于 `friend_links` 分组；日志中以数量、开关和结果摘要覆盖该组原始输入，避免把校验失败的带凭据网址或异常原文写入操作日志，无需修改公共日志中间件。

提交校验与规范化规则：

- 请求必须包含 `friend_links` 分组，分组内包含 `enabled`、`link_count`、`expected_revision` 以及非空时的 `links`；恢复确认字段为该组内的 `replace_invalid`，省略时为 false。每条记录必须明确提交全部六个字段，包括关闭状态的布尔值。提交前按当前列表顺序重建连续行索引，服务器校验列表结构与数量。
- 零条记录由 `link_count=0` 明确表达；只有在这个条件下才允许省略表单无法表达的空数组 `links`。整组缺失、记录数不匹配或某一行被截断都必须报错，防止异常请求清空配置。
- 全部记录先通过校验，再将总开关和列表作为单个配置值原子写入。对每个编辑行都校验必填字段，空白新增行须由管理员删除后再保存，不静默丢弃。
- 名称和网址去除首尾空白；非空记录必须同时提供名称与网址，禁止把缺字段行静默丢弃。
- 网址使用框架的 HTTP/HTTPS URL 校验，拒绝脚本协议、相对地址、控制字符、反斜杠及含用户名／密码的地址。所有启用和停用记录遵循同一规则。
- 生成独立去重键：协议与主机名转小写，去掉协议对应的默认端口，将缺省根路径统一为 `/`。保留路径大小写、非默认端口、查询参数的内容与顺序、片段；同域名不同页面可分别添加。按去重键阻止重复，展示地址保留管理员提交并去除首尾空白后的有效网址。
- 仅保存明确列出的字段，`link_count`、指纹和异常恢复确认均不进入配置 JSON。前台文字和属性统一转义，`rel` 从白名单生成；表单动态增减行使用模板克隆和文本／值赋值，避免把名称或网址拼入 HTML 字符串。
- 配置解析返回「缺失」「有效」「异常」三种状态。记录不存在时提供初始空列表；记录存在但值为 NULL、空字符串，或 JSON 结构、字段类型、字段内容异常时，前台隐藏整个模块，后台保留数据库原值并显示异常提示。展示端也检查链接协议和关系白名单，防止旧数据或人工导入的数据绕过保存校验。
- 异常配置只在管理员选中「确认使用当前列表替换异常配置」并保存后替换。这个恢复选项默认关闭，仍须通过配置指纹检查；原始配置可以在只读文本框中查看，所有内容转义展示。关闭总开关也不能自动覆盖尚未确认的异常配置。
- 保存与展示均无需访问外站，不引入探测、重试或队列。

保存冲突保护通过现有唯一设置键和数据库条件写入实现，具体约定如下：

- 配置指纹使用 SHA-256，区分记录不存在、值为 NULL、值为具体原始文本这三种状态。它用于检测旧页面；权限仍由后台认证与 CSRF 保证。
- 已有记录保存时，先读取数据库当前原值并与提交指纹比较，再通过同时匹配唯一设置键和该原值的条件更新写入。必须检查实际更新行数；并发导致条件失效时按冲突处理，禁止再执行无条件更新。
- 初次保存只允许插入新记录。两个初次保存竞争唯一键时，只将该键的唯一约束冲突转换为编辑冲突；其他数据库错误正常报告，不使用可能忽略其他数据库错误的通用忽略写入。
- 不能仅在应用层比较指纹后执行无条件 `updateOrCreate`；数据库写入本身必须附带旧值条件。

读取和及时生效约定：后台表单和符合展示条件的主站首页从写库按唯一键读取这一条配置，不使用 `SiteSettingsBag` 中可能缓存的 `friend_links`。首页每次增加至多一次有唯一索引的读取；其他页面和托管站不执行这次读取。新功能不改造全站缓存，也不需要为自己的保存调用缓存清理。对保存成功后新开始的服务端首页渲染，必须使用最新已提交值；保存前已在渲染的请求可能仍显示旧值，已经打开的页面需要刷新。

数据流：

```text
网站设置编辑区 -> 保存控制器 -> 校验与冲突保护 -> site_settings.friend_links
                                                        |
首页控制器 <------------- 按唯一键直接读取写库 -----------+
    |
    +-> 主站 + 正常首页第一页 -> 已启用链接 -> 公共页脚组件
```

首页控制器复用传入请求算出的首页状态，在站点上下文已解析且为主站时提供 `friendLinks`，默认值为空列表。公共组件接受该数据，主题层承担摆放与展示，不查询数据库。站点上下文未解析或为托管站时始终得到空列表。首页预览沿用同一控制器数据，不另写基于后台地址的首页判断。

**7. 主题兼容与改动范围**

公共组件接入基础页脚及 26 个独立主题页脚，覆盖仓库全部 28 个主题。基础页脚中的 `default`、`apple_support_clone` 可共同受益。企业和法律主题有独立网格结构，组件应放到页脚整行容器内，避免挤占现有列。

共用样式放入新增的 `public/assets/css/friend-links.css`，采用友情链接专用类名前缀并继承主题颜色。现有公共 head 片段 `site.partials.seo-head` 仅在 `friendLinks` 非空时加载该文件，沿用该片段已有的公共页面资源输出方式，并保留现有 SEO 字段。其他页面不加载这项资源。每个主题只接入公共页脚组件并处理容器位置。

系统生成的新主题由 `ThemeScaffoldWriter` 默认引用公共友情链接组件。它的布局已经包含公共 head，因此能自动取得独立组件样式。草稿阶段检查生成文件保留组件引用；真实渲染在测试环境中安装生成主题后验证。现有生成草稿的安全示意预览继续保持，不增加草稿 Blade 执行权限；存量生成主题不批量重写。
