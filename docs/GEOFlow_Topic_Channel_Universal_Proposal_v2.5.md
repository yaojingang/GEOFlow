日常操作保持三条路径：

| 使用方式 | 用户操作 | 系统完成 |
| --- | --- | --- |
| 单个专题 | 输入标题 → 点击“AI 生成专题” → 查看、调整或发布 | 找文章、去重、分组、导读、摘要、标签、SEO 文案 |
| 批量专题 | 粘贴或导入标题 → 选择生成后处理方式 → 开始生成 | 逐题生成、展示结果、重试失败项，成功项可直接查看 |

**普通专题默认不要求额外人工审核。单个编辑页由用户点击发布；批量生成和专题任务明确选择“自动发布”后，系统可以完成发布。需要人工审核的站点沿用其既有策略。系统后台保留权限、来源有效性、并发与重试保障，用户遇到问题时看到具体原因和处理按钮。**

## 1. 产品范围与底层主线

### 1.1 专题的定义

专题是独立内容类型，主体来自已有文章的二次组合：选文、顺序、分组、导读、摘要、依据和阅读建议。文章仍回答具体问题，分类继续承担归档，专题提供主题结构与阅读路径。

同一篇文章可以参与多个专题，同一个专题中只保留一次。加入或移出专题只改变关联关系，原文章的正文、分类、发布状态和规范地址保持其自身规则。

专题详情可以复用文章详情的页面外壳、作者信息、元数据和内容组件；专题保存为 `Topic`，任务类型保存为 `topic`。专题有自己的列表、详情、发布时间和版本，不生成一条用来伪装专题的文章记录。

### 1.2 一期完整范围

| 领域 | 一期必须完成 |
| --- | --- |
| 内容管理 | 专题列表、单个新建、批量新建、编辑、预览、发布、撤回、回收站及结果记录 |
| 文章组合 | 当前站点文章匹配、手工增减、去重、顺序、简单分组、选文说明与来源关联 |
| AI | 自动选文编排、导读、结构化摘要、标签、阅读建议、SEO 文案及依据检查；支持手工调整 |
| 标题库 | 复用现有标题库，支持粘贴、文件导入和现有 AI 生成标题能力，记录专题使用情况 |
| 任务 | 创建任务增加“文章任务/专题任务”，支持按计划生成专题及三种生成后处理方式 |
| 模板 | 专题列表、专题详情、首页专题模块、模板调用变量及组件规范、模板包兼容与升级 |
| 前台 | 首屏摘要、时间信息、标签、可选评分/星标、来源说明、内链、普通分页及移动端 |
| 搜索 | 统一 SEO 输出、稳定 URL、Sitemap、可见正文、集合结构化数据及 GEO 试点记录 |
| 运行 | 站点隔离、执行回执、幂等、失败重试、取消、来源撤回处理和缓存一致性 |

一期不增加流程画布、可视化建站器、独立模型配置中心、自动跨平台分发、外部开放 API 或新的收藏账户系统。向量召回、复杂实验看板和跨站复制按后续实际需求接入。**一期 AI 生成使用已有模型与服务端文章检索，不以新增向量服务为前提。**

### 1.3 一套内容链路

```text
输入：专题标题 / 批量标题 / 标题库任务
                    ↓
本站已有文章 → 匹配、去重 → AI 选择、编排与摘要
                    ↓
              同一种 Topic 草稿
                    ↓
      手工发布 / 自动发布 / 按需人工审核
                    ↓
             同一种公开专题版本
                    ↓
  首页专题模块 / 专题列表 / 专题详情 / 搜索发现

模板只读取统一展示数据，生成任务只负责内容组合。
```

避免为人工专题、批量专题和自动专题分别建设三套数据模型或发布流程。模型、模板和发布方式分别设置，换模板无需重新调用模型，换模型也不会改变公开地址。

### 1.4 内容数量与独立价值

新建草稿只需标题。推荐选择 6 至 12 篇文章，自动生成目标默认 8 篇，普通专题上限 24 篇。实际少于目标数量但仍有清楚的组织价值时可以成功生成和发布。

集合专题至少包含 2 篇有效且内容不同的文章，并有准确导读。这个要求来自文章聚合的产品定义。2 至 5 篇可以组成窄主题；系统给出文章较少的提醒，不设置人为质量总分、固定组数或强制 FAQ 数量。

文章不足时保存可编辑草稿并说明现有数量，提供“调整文章范围”“选择文章”“去创建文章”和“稍后重试”。专题任务不擅自生成缺失的原始文章，不拿无关文章凑数。宽主题的承诺超过证据范围时，AI 优先缩小导读表述；用户要求保留的必要内容缺失时列出具体问题。

## 2. 配置与默认行为

### 2.1 系统、站点、专题和任务各自负责什么

| 层次 | 职责 | 用户看到的设置 |
| --- | --- | --- |
| 系统 | 统一内容类型、模板契约、生成执行与发布服务 | 沿用现有 AI 配置、任务调度和模板管理 |
| 站点 | 公开范围、活动主题、首页展示及既有审核要求 | 网站设置中的“专题”小节 |
| 专题 | 标题、文章、摘要、标签、模板和可选时效信息 | 一张编辑页，常用字段直接显示 |
| 任务 | 标题来源、文章范围、生成规则、执行计划和处理方式 | 现有任务创建表单中的专题字段 |

配置存入现有站点设置及任务配置机制。单站自动取得站点，不出现无意义的选择器；多站只列当前账号可管理的站点。

### 2.2 网站设置保持精简

常用设置只有：频道名称、导航专题入口、首页专题模块及首页展示数量。默认频道名称为“专题”，导航与首页模块开启，首次有合格专题发布后自动出现；没有公开专题时前台隐藏模块。

活动主题、专题模板预览和替换复用现有网站模板入口。模型复用 AI 配置器。专题列表中的“专题设置”直接进入当前站点对应设置位置，返回时恢复专题列表或未完成草稿。

审核要求、适用范围字段、时效规则、后续操作入口和评分都按需要设置。普通专题默认不启用专业复核，不要求填写专家身份。站点已有强制审核策略时，新专题遵守该策略，页面提前说明。

### 2.3 生成后处理方式

| 方式 | 用户表达 | 系统行为 |
| --- | --- | --- |
| `auto_publish` | 自动发布 | 生成合格版本后直接发布，或按任务设定时间发布 |
| `draft_only` | 保存草稿 | 生成后留在专题列表，用户随时查看、编辑和发布 |
| `review_then_publish` | 人工审核后发布 | 等待已有授权人员审核，审核通过后按计划发布 |

新建普通专题任务和批量 AI 生成默认选择“自动发布”，提交摘要清楚显示站点、数量和处理方式。用户点击“开始生成”或“创建并启动”即授权该批次或任务按所选方式执行，无需逐条再次确认。仅保存任务时保持暂停。

有站点审核策略时默认使用“人工审核后发布”，以一行说明解释原因。只提供用户有权限的处理方式。单个编辑页的“AI 生成专题”默认更新草稿，最终由用户点击“发布”；保存和预览始终不会悄悄公开内容。

### 2.4 通用化

内置模板、帮助、示例和测试使用占位域名、通用角色和明确的虚构数据。模板包含结构与样式，不捆绑其他站点的文章、身份、业务资料或凭证。匹配、日期、语言和链接按当前站点配置解析。

## 3. 与现有系统的接入

### 3.1 当前源码中已经存在的能力与缺口

| 已核对的能力 | 专题接入要求 |
| --- | --- |
| 内容管理二级导航及现有文章列表骨架 | 在“文章列表”右侧插入“专题列表”，复用表格、筛选、分页和表单 |
| `Task`、`TaskRun`、`ProcessGeoFlowTaskJob` 与 `WorkerExecutionService` | 增加 `content_type`；专题分支在文章选题和文章发布逻辑之前分流 |
| 现有任务表单、调度、生命周期、模型执行身份及调用记录 | 复用调度与授权；专题表单只显示适用字段，运行结果可以指向专题 |
| `TitleLibrary`、`Title` 及标题生成服务 | 共用输入能力；专题消耗记录独立，避免影响文章任务的 `used_count` |
| 现有提示词和 AI 配置 | 新增 `topic` 提示词类型和内置规则，沿用模型解析、授权、用量和失败切换 |
| `SiteScopedArticleQuery` 显式站点查询 | 复用本站公开文章范围，并补充当前审核、分配和风险资格 |
| `SiteThemeViewResolver`、安装模板和不可变 `ThemeRevision` | 增加专题页面、数据契约、默认组件及兼容修订 |
| `SiteThemePackageGuard` 当前页面清单不含专题 | 增加专题页面映射与可选契约，导出/检查/安装均识别 |
| `ThemeScaffoldWriter` 当前生成首页、分类和文章页 | 生成模板时同时提供专题列表、详情和首页模块 |
| Sitemap、固定链接、SEO 头部和 robots 策略 | 统一接入专题，采用无参数分页，预检既有地址冲突 |

历史源码引用见附录 B；本轮新增核对的任务、标题库、模板包和 AI Agent 是当前工作区证据。表中的专题能力均为拟开发内容。

### 3.2 后台导航位置

```text
内容管理
文章列表 | 专题列表 | 分类管理 | 审核中心 | 回收站

专题列表
[新建专题] [批量新建] [创建专题任务]    [专题设置]
全部 | 草稿 | 已发布 | 待处理 | 更多
```

“待审核”只在有审核流程或待审核记录时显示。原审核中心和回收站继续承载文章；专题自己的审核记录与回收站通过专题列表进入，操作不会送入旧文章接口。侧栏保持“内容管理”，不新增专题顶级工作台。

### 3.3 任务类型扩展

任务增加 `content_type=article|topic`，旧任务迁移默认 `article`。创建表单先选“文章任务”或“专题任务”，然后显示对应字段。已开始执行或已有输出的任务不能直接变更类型，可通过“复制为新任务”处理。

任务调度、启停、运行日志和失败重试共用现有基础设施。输出结果统一具有内容类型、内容 ID、标题和查看入口；原有 `article_id` 保持兼容，专题使用 `topic_id`。一个成功生成结果只关联一种内容类型。

调度扫描必须读取目标站点和专题配置版本，使用实际扫描命令验证启用后的自动入队。保存为启用状态后，任务无需额外点击启动；重复扫描继续遵守同任务串行执行。

文章任务继续走原有生成、审核和分发链路。专题任务以一个主站或托管站为目标，使用该站文章，直接写专题公开版本；不经过 WordPress、远程 Agent 或普通文章分发接口。专题表单隐藏图库插入、文章分类分配和外部分发等无关选项。

旧文章字段 `article_limit` 的界面含义保留；专题任务新增 `topic_limit`，计划与统计统一按内容类型读取。任务列表显示“已生成专题/已发布专题”，文章列表计数不会计入专题。

### 3.4 模板兼容属于开发交付

升级默认主题、官方内置主题以及生成模板的基础骨架，并提供自定义主题可用的专题组件和适配入口。旧模板包仍可安装和使用原有页面；使用新专题契约的包要求目标系统支持该契约。

不可变主题修订中的文件不能原地改写。系统构建新兼容修订，保留原页面与资源，补齐专题依赖并验证后切换。标准主题的适配随功能升级完成，日常创建专题无需运行模板检查。 核心设计升级只替换指纹匹配的未定制组件；已有专题文件中存在客户定制时，保留其整套页面、CSS 和 JS 组合。补齐缺失资源时，新资源兼容旧页面结构，辅助信息的展开入口被样式隐藏时保持内容可见。恢复上一版设计后，后续专题发布和普通外观保存继续尊重该设计选择。

首个专题发布前，公开频道保持未开放状态。兼容检查可以在内部预览上下文中渲染空频道，并在切换后回读实际生效的主题绑定；检查成功后再发布首个专题。主题文件损坏或切换失败仍需恢复原绑定。

自定义主题能采用已有外壳时自动使用标准专题组件；无法确定外壳或首页插入位置时，提供预览及“适配当前模板”入口。草稿和生成结果继续可用，自动发布等待模板就绪并提示下一步。模板适配的一次操作同时处理专题列表、详情与首页模块，避免要求运营逐页修补。

当前通用远程主题发布能力尚未开放；本期使用已有本地安装、管理和托管站修订机制完成接入，不扩大链池专用发布路径的用途。专题功能不要求先建设通用远程主题发布平台。

## 4. 三条使用流程

### 4.1 新建一个专题

1. 从“专题列表”点击“新建专题”，填写标题。站点自动取得，模板默认使用当前站点的标准聚合模板。
2. 点击“AI 生成专题”。系统保存草稿，按本站文章范围匹配并生成选文、分组、导读、摘要和标签。
3. 编辑页直接展示结果，可以删减文章、调整顺序、修改文字或切换模板。只调整某一块时使用该块的“获取建议”，对照当前内容后采用；已修改内容受保护。
4. 点击“预览”或“发布”。普通专题直接发布；有既定审核要求时按钮显示“提交审核”，具备相应权限的人可在同一页完成发布。

AI 未配置或暂时不可用时，可以继续手工选文和编辑。首次空草稿不要求填写摘要、分组、评分、FAQ、有效期或高级匹配条件。

新建页保留本次尚未提交的输入，列表入口可显示“继续新建专题”。保存成功后进入该专题编辑页，列表的“新建专题”打开一份空表单。生成中保存时，生成结果与未采用建议继续归属刚保存的专题；通过 AI 工作台打开另一份草稿时也复用同一保存流程；停止生成保留当前输入，后续返回不会混到另一份新建表单。

### 4.2 批量新建专题

点击“批量新建”，在一个轻量表单中粘贴每行一个标题或上传 CSV，选择文章范围、模板和生成后处理方式。可选择“只创建草稿”，用于先建立标题清单。

提交前展示识别标题数、重复数、站点和处理方式。仅异常行需要修正，正常行可直接开始。AI 逐题生成，结果页显示已发布、草稿、待审核、待处理及具体失败项，每条都有“查看专题”。支持只重试失败项，离开页面后结果继续执行并可找回。

这个入口适合一次性工作。持续按标题库取题时，点击“创建专题任务”，已填标题和设置可以带入任务表单，无需重新录入。

### 4.3 创建自动专题任务

在任务管理点击“创建任务”，选择“专题任务”。从专题列表进入时自动预选该类型。

常用字段：任务名称、目标站点、标题库、文章范围、生成规则、模板、专题数量、执行计划、生成后处理方式。规则默认“按标题聚合本站文章”，模型默认当前用户可用的推荐模型；界面仍显示实际使用的模型和规则名称。

标题库旁提供“选择已有”“新建并导入”“AI 生成标题”。生成规则旁提供“使用默认规则”“编辑规则”和少量常用要求，如适合人群、内容语气、建议分组。新建标题库或配置模型后返回原任务，保留输入并刷新选项。

“保存任务”保持暂停，“创建并启动”开始按计划执行。启动后记录每个标题的生成结果，任务详情可查看专题。默认一轮消费标题，不循环生成重复专题；需要维护同主题专题时选择“更新已有专题”。

新任务的运行结果、生成数和标题使用记录从零开始。编辑已有任务保留这些记录，按钮区分“保存设置并暂停”和“保存并继续运行”。标题库为空或已用完时可以保存任务，执行显示“等待新标题”和“补充标题”；补充后回到原任务，不制造备用标题。

### 4.4 更新已有专题

人工编辑：打开专题、调整内容、发布更新，公开页继续使用上一个安全版本直至新版本发布。

任务维护：高级选项“遇到已有专题”支持“跳过重复”和“更新已有专题”，默认跳过重复。维护任务只更新自己关联的专题，或用户明确绑定的专题。默认保护人工修改；内容变动触及已修改字段时保留新建议并显示“有更新建议”。

用户可对某个专题选择“继续自动更新”或“暂停自动更新”。主动撤回或放入回收站后自动维护暂停，任务不能将其重新公开。专题任务暂停不会撤回已经发布的专题。

## 5. 体验原则与操作文案

### 5.1 日常流程保持清楚

后台继承 GEOFlow 当前的浅底、蓝色主操作、表格与主次表单布局。前台继承站点字体、颜色、圆角、导航和页脚，参考截图的编辑式信息层级。当前界面的五项方向已由截图与现有产品确定：运营用户、既有后台样式、清楚的摘要层级、键盘与移动端可用、轻量操作反馈。

操作原则：

- 入口固定，单个、批量和任务都能从专题列表到达。
- 一张编辑页承载内容与发布，常用操作明确，高级项折叠。
- 默认值可以完成普通流程；评分、专家、日期、FAQ、封面和分组按需显示。
- AI 结果在原页面可查看、可编辑；运行日志和内部版本放在展开区域。
- 发布检查在点击前或提交时自动完成，问题直接对应内容与修复按钮。
- 提醒允许继续；实际无法完成的动作写明文章、配置或字段，并提供下一步按钮。
- 运行完成、复制成功、保存失败均有明确反馈；不伪造百分比或预计完成时间。
- 保存失败保留输入，站内跳转返回原表单；安全返回地址取当前列表的筛选与页码，恢复编辑缓存时忽略旧缓存的返回参数。正式系统在关闭或离开有未保存内容的页面时提示，不默认长期保存敏感内容到浏览器。
- 编辑缓存记录基于哪个工作稿版本及是否有未保存修改。工作稿已更新时，默认显示最新内容；旧版本的未保存输入保留，并提供“使用最新内容”“载入上次输入”两个按钮。未改动的旧缓存自动清除，显式载入旧输入时仍使用当前版本与站点提交，正常编辑可以继续。
- 文本及数值输入不因失焦重建整张表单，第一次点击按钮即可完成动作；提示更新保留焦点、输入位置和已展开设置。
- 网站设置保留“已保存”和“当前编辑”两份状态。保存后前台生效；查看已保存效果、保存并预览和恢复已保存设置分别说明结果。
- 页面不存在、已删除或尚未公开时提供明确空态和返回入口，不能改为展示另一个对象。

### 5.2 页面状态与建议文案

| 场景 | 用户看到的文案 | 操作 |
| --- | --- | --- |
| 首次进入 | 把已有文章整理成专题。输入标题，AI 会帮你选文、分组并生成摘要。 | 新建专题、批量新建；下方可创建专题任务 |
| 尚无 AI 模型 | 还没有可用的 AI 模型。配置后可以自动生成，也可以先手工整理。 | 配置 AI、手工新建 |
| 模型繁忙或超时 | AI 暂时没有完成，已保留你的标题和设置。 | 重试、选择其他可用模型、继续编辑 |
| 没有相关文章 | 本站暂未找到与这个标题相关的已发布文章。 | 调整标题、扩大文章范围、去创建文章 |
| 只有一篇有效文章 | 已找到 1 篇文章。再补充相关文章，就可以组成专题。 | 选择文章、调整范围、保存草稿 |
| 少于建议数量 | 已选择 4 篇相关文章，可以继续发布。 | 查看选文；不强制额外确认 |
| 空标题库 | 标题库还没有标题。导入一批标题后，任务会按计划生成专题。 | 导入标题、AI 生成标题、选择其他标题库 |
| 标题库已用完 | 本轮标题已处理完，任务正在等待新标题。 | 补充标题、查看结果 |
| 连续新建 | 上一个专题已保存。现在可以创建下一份。 | 新建专题、返回上一个专题 |
| 取消批次 | 本批已停止，已完成结果保留；还有 9 个标题本次未执行。 | 继续剩余标题、查看已完成结果 |
| 设置尚未保存 | 有尚未保存的修改，前台仍使用已保存设置。 | 保存设置、查看已保存效果、恢复已保存设置 |
| AI 已准备建议 | 当前文字已保留。对照建议后，可以采用这一条。 | 采用建议、保留原文 |
| 导入格式有误 | CSV 的引号没有闭合，原有标题与设置已保留。 | 重新导入、粘贴标题、下载示例 |
| 同主题已存在 | 已有同主题专题，本次已跳过。 | 查看已有专题、改为维护此专题 |
| 当前模板需要适配 | 当前模板还没有专题页面，内容已保存。 | 适配当前模板、预览、选择已支持的模板 |
| 来源文章被撤回 | 这篇文章已撤回，相关内容已停止展示。 | 查看影响、AI 重新整理、手工替换 |
| 人工修改与自动更新相遇 | 已保留你的修改，AI 的新建议可以单独查看。 | 查看建议、采用部分建议、继续自动更新 |
| 站点要求审核 | 这个站点设置了人工审核，生成后会进入待审核列表。 | 查看审核设置；按权限提供入口 |
| 发布响应超时 | 正在确认发布结果，请稍候。 | 自动查询原操作；结果确定后提供查看或重试 |

所有“去配置”入口绑定当前站点和安全返回地址。无权限的用户看到可做的动作和所缺能力，不展示无效按钮或其他站点信息。正常文章数少、没有评分和未填写可选项不会额外增加弹窗。

### 5.3 可用性约束

错误紧邻字段，页面级错误可定位到具体区域。文章编排同时提供上移、下移和分组选择，键盘操作不依赖拖拽。[U2] 主要点击目标建议达到 44×44 CSS 像素，兼顾现有组件。[U1]

移动端编辑先显示标题和结果，再显示高级设置；公开阅读先显示核心摘要与选文，辅助信息可展开。长表格可在表格内部滚动，页面不出现异常横向溢出。状态有文字说明，不能仅用红绿区分。设计验收覆盖桌面、375px 及更窄屏幕、200% 缩放、空态、运行态、部分失败态和输入保留。

## 6. 后台入口、编辑页与任务页

### 6.1 专题列表

列表复用内容管理的布局和组件。顶部主按钮“新建专题”，旁边为“批量新建”；“创建专题任务”和“专题设置”为次级入口。避免重复放置两套同样按钮或为专题重建统计大屏。

默认筛选为标题搜索、发布状态和关联任务；站点仅多站显示。表格包含：标题与摘要、有效文章数、关联任务或人工来源、状态、公开更新时间及操作。

状态主要显示“草稿、已发布、待审核、待处理、已撤回”。运行中的行附加“正在生成”；已发布同时有草稿时显示“有未发布修改”。不要把匹配、模型、评分和版本状态堆成多列徽章。

行操作为编辑、预览、查看前台和更多。批量操作支持生成、发布、撤回、移入回收站和重试，逐条回报结果。创建来源显示“手工、批量、任务名称”，可以跳转对应批次或任务。

勾选区显示实际选中数量，全选仅作用于当前结果。切换筛选时清空选择并说明；批量发布按逐项结果计数，文章不足的项保留并给出编辑入口。错误清单中的用户标题、自定义分组和文件文本按文字展示，不能执行 HTML。审核中心、回收站进入后对应标签选中，返回列表保留合理筛选与位置。

### 6.2 编辑页

```text
标题与简介                       发布侧栏
[AI 生成专题]                    状态、模板、处理方式
                                [预览] [发布/提交审核]
文章与编排
已选文章、增减、顺序、可选分组

摘要与信息
一句话结论、关键事实、标签、可选基础信息

更多设置（折叠）
时效标题、SEO 覆盖、可选评分、自动维护与来源说明
```

文章卡片保留标题、短说明和查看原文。删除关联只影响专题，永久排除推荐通过“以后不再推荐”表达并可撤销。每篇文章可上移、下移和选择分组，首尾移动按钮按实际顺序停用。选择页提供搜索、按分类过滤、选择当前结果和取消当前结果，底部保留选中数及“完成选择并返回”。拖拽只是增强交互。

“AI 生成专题”用于建立内容；已有人工修改时默认为“补充与优化”，不覆盖锁定内容。“重新生成”说明将影响哪些字段，用户选择后执行。高级选文建议可以先查看，再采纳。建议卡保留“当前内容”“AI 建议”“采用这一条”“保留原文”，每次只影响说明的字段。缺标题、导读或有效文章时错误留在对应区域，文章不足提示附“选择文章”按钮；补足两篇不同公开文章和准确导读后即可发布。

### 6.3 专题任务表单

| 区域 | 常用字段与行为 |
| --- | --- |
| 类型 | 文章任务 / 专题任务，切换只显示适用字段 |
| 基础信息 | 任务名称、目标站点；单站隐藏站点选择 |
| 标题来源 | 标题库、剩余可处理标题、导入及 AI 标题生成入口 |
| 内容来源 | 全部本站文章或指定分类，可选排除条件 |
| AI 规则 | 内置聚合规则或自定义专题提示词，使用模型可见 |
| 展示 | 当前站点支持的专题模板，默认标准聚合 |
| 计划 | 本轮专题数量、生成间隔和已有计划组件 |
| 生成后 | 自动发布 / 保存草稿 / 人工审核后发布 |
| 高级 | 每题建议篇数、时效模式、重复处理、自动维护和预算限制 |

底部摘要示例：“在本站使用‘使用指南标题库’，每小时生成 1 个专题，共 10 个，生成后自动发布。”摘要只列实际设置；修改数量或间隔时即时更新摘要，并保留保存按钮的点击与键盘操作。

切换类型时保留尚未提交的同类型输入，服务器忽略另一类型字段。任务创建后类型固定，另建类型使用独立表单；编辑任务只改配置，既有运行结果和进度继续保留。标题库入口选择的库成为当前任务的标题来源，任务名称和规则保留。专题任务的 `need_review` 与处理方式统一派生，不能出现“保存草稿”却继续被原文章发布扫描器发布的情况。

### 6.4 任务结果和设置引导

任务详情区分生成数量、已发布数量、草稿数量、等待处理数量。每次运行显示标题、结果、耗时及查看入口；模型与使用量放在详情中。专题运行结果跳转专题编辑页，文章运行结果仍跳转文章。

详情只显示该任务实际回执。创建或启动任务不增加已生成数量；跳过重复、待补充、失败、草稿、待审核和已发布分别计数。任务与专题按稳定任务 ID 关联，改名后来源文字、筛选和回链同步；迁移既有数据和初始化演示记录也补齐相同关联。运行回执保留当次结果，结果页同时显示当前内容状态；人工补足、审核或发布后当前计数更新，首建已生成统计按唯一有效输出计算，不能把后续撤回当成从未生成。修改任务配置后保留结果，恢复运行使用新配置；暂停或取消期间的旧运行不能随后发布。

AI 工作台已有创建任务能力时，同步识别专题类型并提供相同配置目录和结果链接。它整理任务草稿和设置摘要，实际创建与启动仍由现有授权操作完成；没有配置的内容不会被 AI 宣称已完成。

模板状态和 AI 状态只在首次进入、真正缺失配置或执行失败时展示。配置完整后不常驻长检查清单，也不增加全局“专题准备度”页面。

## 7. 前台专题展示

### 7.1 保持原站视觉与信息架构

专题阅读区采用与后台同类的无衬线字体、蓝色主操作、轻量边框和清楚的正文层级。站点 Logo、导航、页脚与文章页继续使用当前主题。专题标题根据实际内容宽度平衡换行；主题预留的空白辅助列应释放给专题阅读区。样式作用域限定在专题组件。

默认频道名为“专题”，可由站点配置覆盖；首批合格专题发布后再开放导航入口。首次尚无公开内容时保持入口隐藏。站点设置保存`topics_public_opened_at`，由第一次成功发布合格专题时写入；草稿创建和候选任务不能设置该标记。该标记用于区分尚未开放与开放后的空频道，停用功能不删除历史标记。上线后若全部专题被撤回，频道返回可控的维护/空态页面并设`noindex`、移出 Sitemap，不把草稿或错误堆栈展示出来；单个被撤回专题返回安全的 404。

频道提供专题名称/导读搜索和标签入口。默认显示八个标签及当前选中标签，其余通过“更多标签”展开；“全部专题”与“查看全部”可以恢复完整列表。桌面列表使用两列阅读条目，手机使用单列，每项展示真实文章数量、摘要与整理日期。

频道分页默认 20 条，固定排序为编辑展示顺序升序、首次公开时间降序、专题 ID 降序。第一页为`/topics`，后续为`/topics/page/{page}`；`/topics/page/1`及兼容收到的`?page=N`统一 301 到规范路径，页码必须为正整数，越界返回 404。该路径避免被当前`/*?*`抓取规则阻断，分页采用普通 HTML 链接。排序变动期间允许相邻请求的列表变化，测试应验证无重复 ID、无草稿和无跨站内容。

核心布局将每个非空分组接入阅读路线，合法分组名“0”也有对应锚点。无分组时提供顺序阅读入口。自定义布局统一提供选文起点，由布局自行组织更细的导航。桌面侧栏提供摘要、来源文章、分组与常见问题目录，并高亮当前锚点。

桌面长页面可采用内容＋轻量目录双栏，移动端目录放正文之前并可折叠。锚点使用稳定分组 ID，不因分组改名随机变化；固定头部不得遮挡定位标题。

### 7.4 卡片与可信信息

文章卡片默认展示标题、一段短说明、最多两个必要标签及详情链接；日期按内容需求展示，避免每张卡片同时出现创建、发布、更新、抓取和复核五个日期。

文章标题、说明、标签等来自已发布的专题展示快照。网址由统一 URL 服务根据当前规范路径生成；来源安全状态在展示前核验。未经核验的适用范围、版本兼容性、专家身份或有效性标签不公开；机器推断不得直接转成可信背书。

一期不展示匹配分、未经真实依据的专业星级、效果比例、阅读完成率、收藏人数或“AI 推荐指数”。有编辑评分时必须同时展示评分口径、维度、日期和依据；没有真实数据时不通过装饰性数字制造可信度。

### 7.5 首屏结构化摘要与参考页式信息模块

参考页面的可取之处在于先给读者一个可扫描的实体摘要，再展开正文。GEOFlow 专题页采用同样的阅读顺序，字段全部来自已发布专题版本，图片中的具体数字、日期、名称和星级不作为默认值。

```text
站点标识 · 编辑审核（仅有适用当前版本的真实记录时显示）
H1：带时效词的专题标题
一至两句摘要：主题、适用对象、范围、关键结论和更新时间
[开始阅读] [访问相关入口] [收藏] [分享]（按站点能力显示）

编辑综合评分 8.5 / 10   星形填充4.25/5（虚构示意；评分卡有效时显示）
完整性 8.4   清晰度 8.5   证据充分度 8.4   时效性 8.7   易用性 8.6

基础信息
适合人群、覆盖范围、使用方式、语言、访问条件、价格或费用、首次发布、公开更新、内容复核、技术核验

标签
主标签、主题标签、场景标签、对象标签、范围标签（最多8个）

来源与审核
编辑或审核角色、审核方式、依据来源、最近一次复核、变更说明

结构化摘要
一句话结论、关键事实、适用范围、不适用范围、阅读建议、更新说明
```

首屏先交代主题与阅读入口，正文开头给出一句话结论。摘要与完整事实依据在服务端 HTML 中直接输出；关键要点、引用片段和阅读建议使用原生可展开组件。较长的原文片段可在有键盘焦点的区域内滚动阅读。正文、分组标题、标签和文章链接保持可复制、可访问、可索引。摘要优先回答“这是什么、适合谁、覆盖什么、截至何时有效”，每个关键事实保留来源或审核记录。摘要建议控制在 80 至 180 个汉字，超出时按语义分段，不为满足字数删去限定条件。

基础信息使用键值行或定义列表，缺少真实值时省略该行。`访问正常`、`中文`、`付费产品`等截图中的字段只能在系统有相应探测或站点配置时显示。访问状态、价格、账号要求、语言和技术核验属于事实字段，不能从专题名称或文章内容推断。

评分卡是可选的质量解释组件。实际编辑完成评分时标为“编辑评分”；AI 根据量表生成时标为“AI 辅助评分”，显示模型评估方式与依据，不声称已由编辑或专家审核。默认隐藏，生成专题不要求评分。专题启用评分卡后，默认维度为完整性、清晰度、证据充分度、时效性和易用性，站点可减少维度但不能改写评分含义。未启用或没有可核验评分时，前台省略评分卡。每个维度显示 0 至 10 分、短说明、评分日期和评分依据入口；总分为加权平均并保留一位小数。评分卡服务读者判断，不表示搜索排名、专业认证、用户口碑或 AI 引用概率。

星号只作为数值的视觉表达，统一按总分除以 2 映射为五颗星的连续填充；8.5/10 对应 4.25/5，不绘制成五颗全星。辅助文本保留精确分数，装饰星形对辅助技术隐藏。没有真实用户评分时，不使用“用户评分”“五星好评”或`AggregateRating`结构化数据。真实用户评价与编辑评分必须分成两个组件，来源、计数、时间和统计口径分别展示。

标签来自专题展示快照。主标签用于归类，其他标签说明对象、场景、语言、版本或内容类型。标签应能在摘要或正文中找到对应语义，限制数量和长度，避免把标签区变成关键词堆叠。标签链接只有在站点有稳定的可浏览集合页时才启用，否则显示为文本。

来源与审核模块采用“谁在何时以什么方式检查了什么”的句式。公开显示角色名称、审核方式、依据类型和日期；个人姓名、内部任务号与私有文件路径按权限隐藏。`首次发布`、`公开更新`、`内容复核`和`技术核验`含义分开，某个日期缺失时留空，不用草稿创建时间代替。

移动端顺序为标题、简短导读、少量标签、时间与主要动作、紧凑的分组阅读路线、核心结构化摘要、文章分组与选文。评分、基础信息、相关标签和来源审核合并为“查看专题信息与来源”的可展开区域，默认折叠；展开只显示当前专题实际具备的字段。核心摘要不因辅助信息较多被推到页面后半段。长英文词、URL 型文字和自定义分组能够断行，列表和详情在窄屏保持无页面级横向溢出。桌面端评分卡和基础信息放在正文侧栏，正文仍直接展示核心摘要，侧栏不承载唯一结论。收藏和分享只复用部署站点已存在的能力；一期不新增收藏账户或分享接口。

### 7.6 时效性标题、有效期与更新表达

专题名称是稳定主题词，公开标题由已发布版本的受控标题规则生成，稳定 URL 保持不变。时间词使用该版本记录的年度、复核截止日或产品版本；系统日历跨年时不自动把 2026 改成 2027。自动任务可以采用真实整理日期词；涉及内容覆盖年度或“截至某时有效”的表达仍须具备相应来源依据。

| 场景 | 标题模板示例 | 允许条件 |
| --- | --- | --- |
| 年度版 | `2026年产品使用入门：从首次设置到常见问题` | 内容和依据明确覆盖 2026；延长年度需重新检查并发布 |
| 整理日期 | `2026年9月整理：产品使用入门与常见问题` | 采用本次实际内容整理日期；表述只说明整理时间，不宣称来源事实截至该月仍全部有效 |
| 截止日期 | `截至2026年9月的GEO专题页设计指南` | 来自该版本真实复核日期和覆盖范围，时间固定 |
| 活动/事件 | `2026年示例大会参会指南` | 开始、结束、地点及活动状态有依据；时钟只能改变已发布的时间提示 |
| 持续更新 | `产品使用入门：持续更新` | 有公开更新记录；最近 90 天有实际复核，并约定下一次复核 |
| 常青主题 | `产品使用入门` | 用户或任务明确选择常青，内容不承诺需要时间窗口的事实 |

系统允许年份、月份、季度、版本号、`截至YYYY-MM`、真实`YYYY年MM月整理`及有依据的`持续更新`。活动附加提示采用“开始时间未到”“活动时段内”“结束时间已过”，准确描述已核验时间窗口。`即将开始`仅在发布快照设定的提示窗口内使用，默认开始前 7 天；`已结束`要求核验实际结束状态。取消、延期或实际举办情况需更新依据并发布新版本；站点有审核要求时按其策略处理，不能仅凭时钟推断。`最新`、`最全`、`第一`默认禁用，比较性宣称需可核验证据和人工确认。

搜索文案中的“可核验”“可复核”说明内容能够接受检查，可以用于具备来源的常青专题。“已核验”“已复核”、明确核验截止日期等完成性宣称需要实际记录。文案校验区分这两类语义，避免要求运营为能力描述补填虚构日期。

时效模式固定为 `evergreen / composed_at / annual / version / as_of / event / rolling`。`composed_at` 只展示实际内容整理日期，来源事实的有效性仍分别判断；其模式状态视为常青表达，不赋予当前有效期背书。其他时效模式按实际范围和必要依据检查，未知模式返回字段错误。

时效策略保存在工作草稿，发布前冻结到`freshness_snapshot_json`，至少包含模式、模板及覆盖值、版本/年度、有效起止、`public_from`、`last_verified_at`、下次复核、时区和到期处理规则。公开服务只读当前已发布快照，草稿中的日期或标题编辑不改变现有公开页面。

`freshness_status`为当前时间和公开快照计算出的运行状态，生命周期与审核状态独立管理：

| 时效状态 | 计算条件 | 公开处理 |
| --- | --- | --- |
| `evergreen` | 明确选择常青，且没有尚未处理的时效型主张 | 已发布且通过资格检查时公开 |
| `unknown` | 非常青模式的必需日期、版本或依据缺失/无效 | 阻断该时效版本发布；已公开受影响主张按风险抑制，不能自动标成常青 |
| `expired` | 到达有效期结束，或持续更新模式到达复核期限 | 显示过期与原覆盖期；价格、活动日期、兼容性或安全主张失效时抑制；历史资料可在明确历史范围下保留 |
| `scheduled` | 尚未到有效期开始 | 已授权公开的活动指南可提前展示真实未来日期；不符合预公开策略则不公开 |
| `active` | 日期、依据有效，处于允许的有效窗口 | 正常资格检查后公开；不代表已核实活动实际举行 |

状态优先级为输入无效 → 到期 → 有效期未开始 → 当前有效；常青按明确模式单独处理。实际时间采用 UTC 存储并保留 IANA 时区；有效区间采用`[effective_from, effective_to)`。日期型结束日覆盖该地整天，转换为次日本地零时的排他边界；非法时区、结束早于开始及夏令时歧义返回字段错误，不能默默改日期。月/季度/年度封面词只改变标题模板，实际有效窗口分别保存。

`public_from`表示允许公开的起点。已选择自动发布或审核后发布的任务，可以在指定时间发布绑定的确定版本；手工草稿不会仅因时间到达被发布。发布任务重新核对权限、任务启停、内容版本和来源资格，版本改变时取消旧计划。时效检查任务只处理已公开内容的时间提示和失效，不承担发布动作。已发布活动指南可在未来活动开始前公开，内容有效期和公开时间分别管理。撤回内容始终需要明确恢复操作。

公开读模型统一生成 H1、Title、OG、摘要中的时间提示、时效状态和 JSON-LD 日期。动态提示使用发布版本中的模板，保存运行状态变更记录；年度、版本、固定截至日期或人工核心结论变化须生成新版本并重新检查依据。标题超长时保留完整主题及关键日期，先缩短副标题和站点后缀；H1 允许换行，字符长度作为提醒。日期解析失败使用基础标题显示，同时保留`unknown`和风险处理，不能获得常青有效性。

时效任务每 5 分钟检查到期索引并记录提醒，公开请求在本地依据同一快照重新计算状态。缓存到期不得晚于下一个时间或评分边界，队列停机仍能停止无效时间宣称。只改变时钟提示且未改变主体信息时，不刷新`dateModified`或 Sitemap `lastmod`；到期撤回、核心事实更新或公开正文有实质变化时记录真实内容变化。

### 7.7 结构化摘要的 GEO/AEO 写法

专题正文按“答案先行、证据跟随、边界明确”的顺序编排。首屏的一句话结论回答核心意图，关键事实模块提供可独立引用的定义、数字、条件、比较或步骤，文章卡片承担深入阅读。每个结论标记适用范围和日期，涉及外部事实时提供可点击来源。

专题可以提供以下可选模块：

| 模块 | 面向读者的问题 | 发布要求 |
| --- | --- | --- |
| 一句话结论 | 这个专题解决什么问题？| 1 至 2 句，包含对象和范围 |
| 关键事实 | 哪些事实可直接使用？| 每项事实有来源或专题内文章依据 |
| 适用范围 | 对谁、哪个版本、哪个地区有效？| 只显示已确认范围，未知写明待核验 |
| 不适用范围 | 哪些情况不应照用？| 涉及风险、时间或版本时优先填写 |
| 阅读建议 | 从哪里开始，为什么这样安排？| 与分组和文章顺序一致 |
| 更新说明 | 这次改了什么？| 说明日期、范围和影响 |

这些模块可以同时服务自然语言问答、搜索摘要和人工阅读。它们不能替代原文证据，不能通过拆成大量短段落或重复同义词制造“AI 友好”表象。Google 公开指南强调基础 SEO、可抓取正文、独特且有帮助的内容仍是生成式搜索的基础；结构化数据必须与可见文字一致。[S8]

### 7.8 让读者获得组织价值

专题导读说明为什么收录这些文章、建议从哪里读起及不涵盖的范围。文章说明可以突出在本专题中的作用，不强制逐张撰写新的长段落；重点文章优先补充选文理由。

常见问题与核心回答均为可选项。只有标题和链接时，审核重点是相关性与组织；新增参数、条件、兼容性、效果数据或操作建议时，需保留可核验依据，并按站点策略完成相应复核。不得为凑“GEO 模块”编造 FAQ。

阅读路径、选文理由和真实复核信息作为通用内容组织能力保留。学习进度、收藏账户及阶段完成按钮不进入一期；需要这些功能时另行评估，避免把内容集合扩展成新的学习平台。

### 7.9 内链与可选后续操作

首页或导航指向频道，频道指向专题，专题指向文章；文章页可展示最多 3 个高相关且公开的专题。专题页最多展示 3 个相关专题，没有合适对象时不显示。

默认不改文章正文，回链作为可复用局部组件插入。所有回链过滤当前站点、公开版本与安全状态，避免草稿标题通过文章页泄露。

后续操作复用当前站点已经存在且被授权的页面或表单，例如了解产品、查看资料、联系支持；没有对应能力时不显示入口。内容适用范围与组织实际提供产品或服务的范围分别管理，不能从文章主题推导服务承诺。

专题模块不新增销售漏斗、支付、资料授权下载或客服系统。引用已有入口时验证其公开状态、当前站点与允许的 URL；未配置时不生成占位联系方式。


### 7.10 首页专题模块与模板选择

首页增加独立专题模块，默认位于最新文章区之后，显示最多 3 个已公开、有效的专题；有真实置顶时优先，否则按公开时间排序。模块具有频道标题、简短说明、专题卡片及“查看全部专题”入口。没有有效专题时整个模块隐藏。

专题卡片展示标题、摘要、有效文章数、少量标签和真实内容更新时间。首页不调用模型、不扫描全站文章；使用统一公开读模型。模块位置和样式随活动主题确定，网站设置可以关闭或调整展示数量。

默认提供标准聚合、阅读指南、资讯盘点三种详情布局，共享同一套组件与数据。编辑页预览、模板预览和历史预览绑定同一个专题 ID 与明确草稿或公开版本，浏览器后退仍读取原对象；每份新建草稿使用独立预览标识，保存后映射到已保存专题，不回退成下一份空表单；切换不换成其他演示内容；用于当前专题和设为后续新专题默认模板分别说明。标准聚合强调摘要和选文；阅读指南强调分组顺序；资讯盘点强调真实时间与变化。切换布局只调整呈现，不能生成新的日期、评分或结论。自定义主题可在契约内扩展布局，见第 14 节。

本章为正式设计规范；本轮已验证模拟原型的桌面与移动端布局，正式主题渲染、服务端内容、可访问性及兼容验收在实施后执行。

## 8. 文章匹配与 AI 生成

### 8.1 两段生成，输出统一草稿

第一段从当前站点召回文章，使用标题、关键词、摘要和需要时的净化正文。先过滤删除、撤回、无权公开、未分配到该托管站及已明确阻断的内容，再做相关度排序与去重。

第二段交给 AI：先从候选中选择文章并建议分组，再读取被选文章的必要正文片段，生成导读、摘要、标签和选文说明。AI 只能选择给定的文章 ID；生成的事实和结论关联实际来源片段。服务端检查结构、ID、来源和字段后保存为同一种草稿。

模型不能直接改数据库、文章状态、模板文件或公开地址。渲染页面也不调用模型。普通生成执行完毕后，编辑和查看不继续消耗模型额度。

### 8.2 简单且可解释的匹配

默认主主题词来自标题，AI 可以生成少量相关表达以扩大召回，但范围仍限本站可公开文章。用户可指定分类和排除词；高级必须词组默认隐藏。

基础相关词采用 OR；高级必须词组为组内 OR、组间 AND。排除词默认检查标题和关键词，避免正文提到反面例子时误排整篇文章。来源资格与相关度分别判断，相关度高也不能让不可公开文章入选。

一期词面排序采用可测试的固定规则：标题命中优先，其次关键词与摘要，再补必要正文；同分以文章 ID 稳定排序。命中字段和表达作为后台解释，AI 再从候选中精排。内部相关度不转换为前台评分、正确率或引用概率。

匹配扫描分块执行并覆盖声明范围，不能把“每批 200 篇”当作全站上限。候选池默认最多 100 篇，AI 选文阶段默认最多接收前 40 篇的压缩信息；记录截断和范围。用户要求的必要内容不能因为截断而被默认为不存在，可以针对缺失分组补充召回。

### 8.3 AI 承担的内容工作

| 内容 | 生成规则 |
| --- | --- |
| 文章选择 | 相关、不同内容、可公开；不强行达到目标篇数 |
| 分组与顺序 | 依据主题组织，允许不分组；每个分组有文章，未分组文章放入“相关阅读” |
| 导读 | 解释专题覆盖范围、收录理由和阅读建议 |
| 一句话摘要 | 回答主题意图，保留范围、条件和必要限定 |
| 关键事实 | 每条有来源文章及片段定位，证据不足时省略 |
| 选文说明 | 说明文章在专题中的作用，避免复述整篇原文 |
| 标签 | 表达真实主题、对象和场景，数量有限；不创建无内容标签页 |
| FAQ | 有真实问题且来源能回答时生成，普通专题可不含 FAQ |
| SEO 文案 | 由实际内容生成 description；标题时效词受服务端规则约束 |
| 基础信息 | 只提取来源明确支持或站点已有配置的字段，未知返回空 |
| 评分建议 | 默认不生成；启用时使用明确量表，标为 AI 辅助评分，不能伪造编辑身份 |

AI 不生成专家认证、用户评分人数、访问正常状态、价格承诺、技术核验时间、虚构来源或自动年度背书。多个来源互相冲突时显示待处理项，或在允许范围内省略该事实，不能用流畅文字掩盖冲突。

### 8.4 提示词与结构化输出

新增内置 `topic` 提示词，与文章正文、质检提示词分开。提示词变量由服务端提供：标题、目标读者、语言、站点内容范围、候选文章、实际来源片段、当前生成要求及输出结构。

使用项目已有 Laravel AI SDK，专题 Agent 采用结构化输出契约，沿用现有模型调用网关、执行身份、用量与授权的失败切换。当前官方资料支持 `HasStructuredOutput` 与 Agent 测试替身；具体运行接口以实施时已安装版本核验。[S13]

现有文章调用若只接收文本提示词，在同一网关补充专题结构化 Agent 调用能力，保留授权和用量边界，文章分支保持原行为。模型不支持当前结构化要求时说明原因并提供换模型或手工编辑，不能跳过服务端校验。

AI 输出固定包含：选文 ID 和分组、导读、摘要、事实及引用、标签、阅读建议、可选 FAQ、待处理事项。时效日期、规范 URL、发布时间、审核人、总文章数和最终 SEO 标签由服务端生成，不能接受模型自填授权字段。

来源文章、用户标题和自定义规则属于输入数据。来自文章正文的“忽略规则”“发布到其他站点”等指令没有执行权。原始材料截断、上下文预算及选择过程记录在运行结果，不能把未读完原文标成完整核验。

### 8.5 质量与失败处理

服务端先做确定性校验：字段类型、允许的文章 ID、站点资格、去重、文章数量、来源片段、长度、标签数量、HTML 净化和来源版本。模型再做一次内容一致性检查，识别明显无依据主张和范围冲突；模型检查属于 AI 检查记录，不能替代人工或专家复核记录。

原文片段保留原始字符位置和校验值。浏览器提交表单时产生的换行转换仅用于文本等价比较，继续核对原始来源的字符范围及校验值；修改正文或片段文字仍需重新核对来源。修改导语或摘要时，未改变的有效证据可以继续使用。

结构或内容不合格时允许 1 次针对错误的自动修正。仍未完成时保留可用草稿，列出具体问题并提供重试和编辑。已经有效的摘要块可以保留，不重复生成所有内容。实际不能保证的事实直接省略；核心主题无法成立时保持待处理。

**不设置默认 80 分、85 分或“GEO 达标分”等发布阈值。** 不启用评分卡、没有 FAQ、缺少封面和文章数少于建议值都不阻止普通发布。站点原有明确风险策略继续适用，但不把文章专用质检配置无差别套到专题。

### 8.6 人工编辑与自动建议

记录字段来源：人工、AI 或站点配置。用户修改内容后对应字段受保护。整页“重新生成”必须明确要替换的范围；默认的 AI 优化保留人工选文、排除、顺序和文字，只补充未锁定内容。局部“获取建议”始终先展示对照，不直接写入人工字段；采用建议是独立操作，可按块使用，也可保留原文。

手工匹配运行只返回建议，用户采纳后写草稿；专题任务的自动选文已由任务设置授权，可以直接形成自己的草稿并按处理方式发布。两条路径共用匹配服务，写入语义分别明确。

### 8.7 评分与星标的完整规则

评分卡默认关闭。编辑评分与 AI 辅助评分各自保存来源、量表版本、维度、权重、说明、依据、时间和评分对象内容哈希。维度可采用完整性、清晰度、证据充分度、时效性和易用性，均为 0 至 10 分。

这些维度评价专题组织质量。参考截图中的功能性、性价比等适合真实产品测评；需要评价某个产品时另绑定实际评价对象、口径和证据，不能用专题质量分代替产品评分。维度分值、权重必须有限且有效，权重非负并至少有一个正值；数据不完整时省略评分，不阻止普通专题发布。

总分采用有效维度的加权平均并保留一位小数。星形用总分除以 2 的连续填充，8.5/10 对应 4.25/5，辅助文本保留精确数值。没有真实用户评价时不显示用户评价人数，也不生成 `Review` 或 `AggregateRating` 来标记专题自评分。[S9]

默认有效期 90 天，并取依据或有效期中更早的边界。标题、摘要、选文、分组、核心主张或安全隐藏发生实质变化后旧评分隐藏；自动维护可重新生成标明来源的 AI 辅助评分，编辑评分需实际编辑重新评价。评分失效不会撤回仍可安全阅读的专题。

## 9. 标题库、导入与批量处理

### 9.1 复用标题库，记录分开

标题库继续是统一内容资产。专题可以选现有标题库，也可以从专题入口新建并导入。标题生成规则明确目标为“专题标题”，优先输出能由本站文章支撑的主题，避免大量仅替换关键词的同义标题。

不为专题新建另一套标题库页面。标题文本、关键词和指纹沿用现有规范化；新增专题使用统计和结果链接。文章任务已有 `used_count/usage_count` 继续保持文章语义，专题使用量从专题运行回执单独计算，不写入这两个字段造成文章任务提前耗尽。

### 9.2 导入形式

支持每行一个标题、单列 CSV，以及包含可选列的 CSV：标题、适合人群、适用范围与限制、文章分类、标签、模板、时效模式、来源覆盖期。普通用户无需准备可选列。沿用现有标题库导入能力，批量新建专题可以直接消费标题而无需先建库。

先解析和检查格式，再展示简短摘要，最后执行。单列 CSV 识别“标题 / 专题标题 / title / topic_title”表头，支持引号内逗号、双引号转义和 BOM。单字段内的换行归一为空格，保持一条 CSV 记录对应一个标题；显示的识别数、保存数与后续专题数一致。标题库导入追加并去重，批量表单导入替换清单时预告影响；原有名称、规则、模板与处理方式保留。格式损坏或读取失败不覆盖原输入，在导入区域持续显示错误和修复入口。包含可选列的文件按列名映射，不把整行字符串误当标题。文件有编码错误、超限和异常行时给出明确反馈。输入文件、逐行结果和错误报告放在私有存储，报告下载重新验证权限。导出处理 CSV 公式注入。

### 9.3 重复与范围

同批相同规范化标题与范围默认去重；同站已有相同主题和范围时默认跳过并链接原专题。其他站点同名不视为本站重复。编辑页提供可选的“适用范围与限制”，批量表单支持统一范围说明和 CSV 每行范围；同名专题可填写明确的不同范围后分别保存，未填写范围仍可正常创建。专题列表在有范围时展示简短范围说明，帮助用户从同名条目中选对编辑对象。

重复行链接本批首次记录或同站真实专题 ID。首次行尚未成功创建时显示“查看首次记录”，不生成伪链接；首次行重试成功后重复行关联刷新。统计中的输入行、不同主题与范围、重复行含义固定。

稳定主题键按站点隔离，以规范化基础标题、显式的 `summary.scope` 和真实时效覆盖范围生成。覆盖范围按模式取年度、月份或产品版本，并在非普通整理日期模式下保留已声明的 `coverage_note`；文章分类、来源起止日期等选择条件先保存为可见范围说明，再参与相同校验。常青及普通整理日期模式的空范围沿用旧标题键；整理日期、前台年份装饰词、站点名称、文章顺序和文章 ID 不单独产生新主题。选文、生成、批次、重试和手工保存共用此键，保存失败保留原输入并就地说明重复原因。标题库里同义表达仅有词面差异时可以提示合并；不能让 AI 根据相似度自动合并两个实质不同的主题。

批量清单转为专题任务时，同名不同范围继续保留为独立生成项。不同范围分别绑定可复用的真实标题资产，标题库中的范围变体带有范围说明和编号，专题保留原始标题。每项范围、占用和执行状态分别记录；任务取题、重试、剩余数量和完成计数按主题与范围计算，不能因为相同 `title_id` 丢弃另一范围。 预览页提供“转为专题任务”，任务设置显示带入项数、专题名称数、标题库项数和每行范围，保留文章范围、规则、模板及生成后处理方式；保存任务时可自动建立标题库。清单带入任务仅处理所选项，标题库中其他标题不自动进入本轮；已有普通文章标题及文章使用次数保持原值。 转为任务默认新建独立标题库；选择文章任务也使用的已有库时，新增的范围标题同样可能被文章任务选用，标题库选择旁说明这一影响，用户可以继续保存。 本批逐行模板与范围配置随当前专题任务保存；另建任务选同库时使用库中显示的标题和新任务规则，需要单独设置本任务范围。

用户选择“更新已有专题”时更新绑定专题，不仅凭标题相似度覆盖任意手工内容。每个目标专题同时只允许一个有效自动维护任务，冲突时引导查看或替换已有关联。

### 9.4 标题占用与完成语义

取题前在短事务内持久记录站点、任务、标题、轮次及占用状态，模型调用在事务之外。占用有租约，技术失败可恢复同一个运行；超过租约后由对账决定恢复或释放，不能无记录地重复选题。

同一执行重试不重新建专题。成功写入可编辑专题及回执后才记一次标题已生成；自动发布失败不重复消耗标题，重试发布即可。草稿、待审核和已发布都属于已生成结果，分别计数。仅保存不完整草稿的失败项保留关联 ID，不计成功生成，重试继续修正该草稿。

专题任务的手工重试继续走原任务队列，重新取得有效执行记录，绑定原生成记录和原专题。任务正在处理其他标题时，先保存重试请求，当前执行完成后再处理；连续点击只保留一次请求。任务暂停、配置改变或专题撤回时明确说明下一步，旧请求不能恢复已经停止的内容。

默认不循环创建同题专题。定期维护只生成新版本，标题使用记录保留首建与维护两类，不把维护次数计为新专题数。

### 9.5 批量结果

成功、跳过重复、等待文章、等待配置、生成失败、待审核、已发布和发布失败都有明确结果。显示总行数和各类计数，能够逐行对账。取消只停止未执行项和当前可停止边界，已发布项继续存在；撤回另用明确操作。

批量发布检查每一条当前版本，允许合格项成功、失败项保留，不把整个批次锁成一个大事务。相同批次请求返回原结果，只重试失败项，不重复成功项。快速双击保存沿用同一次提交；新生成及失败重试交叠处理相同主题时，提交前按站点与稳定主题键再核验，后提交项返回首个结果。同主题已撤回或进入回收站时保留停止公开决定，提供查看回收站或明确恢复的入口。

每批固定文章范围、规则、模板、生成后处理方式和提交时审核策略，重试沿用本批设置；执行前仍核对当前审核要求，不能绕过后来收紧的策略。返回标题与设置读取该批内容。停止后统计“本次未执行”，可用“继续处理剩余标题”建立关联的新执行，只包含未执行行，原有成功记录与原批设置保留。演示异常由原型的独立体验选项开启，普通生成按真实结果反馈。

## 10. 发布、自动更新与来源变化

### 10.1 普通发布保持一步完成

普通编辑页提供“保存并发布”；站点要求审核时显示“保存并提交审核”。一次点击先保存当前完整输入，再检查必要字段、来源、权限、地址和模板，发布或提交确定的内容版本。发布失败时已存工作稿保留，错误对应具体字段并给出补充入口；原公开版保持其有效状态。单独保存、AI 草稿生成和预览不发布。

专题任务和批次已选择自动发布时，由执行身份按该设置发布，系统记录“自动生成/自动发布”和实际内容检查，不能生成“编辑审核完成”或“专家复核完成”的假记录。

站点已有人工审核要求时记录绑定版本的实际审核，包括审核方式、实际操作人、审核时间和专题版本 ID。具备相关能力的人可以在同一页审核并发布；普通站点不要求三个角色或多个步骤。审核通过后计划任务可以发布确定版本，修改正文后旧审核不再授权新内容。

### 10.2 只处理真正影响完成的问题

| 无法直接发布的具体问题 | 默认处理和引导 |
| --- | --- |
| 标题或导读缺失，有效且不同文章不足 2 篇 | 保存草稿，定位字段或“选择文章” |
| 文章跨站、撤回、删除或当前无权公开 | 自动排除，尝试相关替换；不足时说明影响 |
| 核心主张无依据、明确冲突或虚构身份/评分/时间 | AI 修正或省略；仍影响主旨时保留草稿并列出问题 |
| 站点要求审核但尚未完成 | 进入待审核，保留其他正常操作 |
| 地址冲突或模板无法渲染 | 给出受影响地址或模板适配入口，生成结果继续保留 |
| 计划公开时间未到、任务停用或执行权限已撤销 | 保留确定版本和实际状态，按计划或配置恢复处理 |

文章数少于建议值、可选字段缺失、SEO 文案长度和可选评分过期仅为提醒。不要求用户为每条提醒填写“已核实”理由，也不引入默认的发布质量总分。

### 10.3 草稿、公开版本与回执

工作草稿可以编辑，使用内部版本防止并发覆盖。发布前冻结标题、摘要、选文、分组、依据、评分、时效和模板选择为 `TopicRevision`，公开页只读当前公开指针。每次提交审核冻结一个明确版本；审核期间旧公开版本继续提供阅读。用户随后修改或保存草稿，待审核内容保持其提交版本；审核通过只发布该版本，后续草稿留在编辑页并显示“有未发布修改”。

审核记录按专题及版本 ID 持久保存，公开页读取当前公开版本的真实记录。切换公开指针、清空待审核状态或提交下一版本时保留历史审核；发布执行人不能代替审核操作人。未经人工审核的自动发布省略人工审核时间和身份，AI 检查保持独立标识。

手工与自动发布共用服务。校验执行身份、站点、预期草稿版本、当前来源和实际审核策略，短事务内原子切换公开指针，更新真正的内容时间及回执。仅保存未变内容、切换模板或重新公开同一内容时，保留原内容整理时间、内容更新时间、`dateModified` 和 Sitemap `lastmod`；新增选文、摘要或正文组织等实质修改才更新对应内容时间。模型和完整全文检查在事务外执行。

生成任务携带任务配置版本和租约。提交时发现任务暂停、配置改变、人工编辑或较新撤回决定，停止旧任务的写入，保留建议或结果。不能用旧结果覆盖用户后来作出的决定。

保存并发布的请求携带幂等键和请求哈希。相同键与相同内容复用原回执，同键不同输入拒绝并解释；用户后来编辑或撤回后，重放旧请求不再次写入或恢复旧公开版。回执与业务提交同事务，网络超时查询原结果，不能盲目用新键再次发布。回执有效保留期和清理沿用既有 `IdempotencyService` 配置，默认 7 天，不承诺永久复用。成功回执区分“页面已公开”和“索引/缓存更新待处理”。

历史列表和恢复操作绑定当前专题 ID 与所选版本，恢复先形成该专题草稿并核验当前来源；预览、恢复不会切换其他专题或立即公开。用户主动撤回后任务暂停该专题维护，恢复公开需要明确动作。关闭任务只影响后续生成与计划发布，已经公开的安全内容保持其状态。

回收站的“恢复到草稿”清除已删除和专题撤回标记，恢复后可以在草稿列表找到并继续编辑。公开指针为空，来源抑制记录与自动维护暂停保持原状；后续公开仍由用户明确发布。

### 10.4 自动维护的明确边界

| 事件 | 默认行为 | 允许的自动维护 |
| --- | --- | --- |
| 新文章发布 | 原专题保持，更新相关候选 | 已开启维护的专题合并事件、重新整理未锁定内容 |
| 匹配/生成规则改变 | 下次执行使用新设置 | 旧运行不能提交；不据此改写未绑定专题 |
| 来源正文修订 | 失效的转述和主张暂时隐藏 | 重新读取当前来源，生成并检查新版本后按任务方式发布 |
| 来源规范 URL 改变 | 统一 URL 服务更新链接 | 验证同一对象，未变正文无需额外人工审核 |
| 来源撤回、删除或权限收紧 | 卡片及派生内容停止公开 | 自动补选与重写；合格新版本可恢复，不能复活旧失效块 |
| 用户手工编辑 | 保护相关字段与顺序 | 保存独立建议，用户采纳；可明确选择继续完全自动维护 |
| 用户撤回或删除专题 | 停止该专题自动维护与发布 | 明确恢复后重新建立维护授权 |
| 到达计划发布时间 | 只有已授权处理方式的确定版本可发布 | 再核验任务状态、内容版本、权限与来源 |
| 到达时效/评分边界 | 更新提示，隐藏无效评分和事实 | 自动任务可以检查依据并生成新版本，不用当前日期伪造复核 |

自动维护需要开启，默认首建任务只按标题生成并跳过已有主题。事件去抖和发布间隔沿用任务计划，避免每次来源修改都调用模型。

### 10.5 来源依赖与公开读取

导航链接、内容转述和实质主张分别记录依赖。文章标题和说明来自公开版本快照，链接来自当前规范 URL，资格和来源版本在读取时核对。正文变化不影响仍准确的纯导航链接；依赖正文的文字需检查是否仍成立。

来源撤回时同步登记最小失效记录，普通队列完成重组与通知。队列停机仍不能返回撤回文章及其派生内容。只影响可选模块时隐藏该模块；有效文章不足 2 篇或核心导读失效时暂停专题公开并退出 Sitemap。

来源重新公开不直接解除旧文字失效；可以由已授权维护任务检查当前来源、产生新版本并恢复，无需重复的人为审批。恢复记录必须对应实际新内容和检查结果。

### 10.6 时间与前台说明

首次发布、实质内容更新、实际内容复核和技术检查分别记录。生成时间可以显示为“整理时间”；AI 一致性检查可显示为“AI 内容检查”，不能填入人工复核日期。文章浏览量、重试、无变化重算和模板切换不刷新内容更新时间或 Sitemap `lastmod`。[S3]

生命周期保持草稿、已发布、已撤回；审核与运行状态按情况附加。内部任务租约、输入哈希、规则代次和安全状态由系统维护，普通列表只显示用户需要处理的结果。

## 11. SEO/GEO 实现要求

### 11.1 采用有依据的优化，明确适用范围

SEO 指搜索引擎优化；GEO 指生成式引擎优化；AEO 指答案引擎优化。本文将基础抓取、内容组织及可验证引用作为共同工作，平台资格与效果分别观测。

| 参考依据 | 本方案采用的设计 | 需要保留的边界 |
| --- | --- | --- |
| Google 关于 AI 搜索与网站的公开说明 | 维护 SEO 基础、可读正文、清晰组织与可发现链接 | 不承诺特殊标题、固定篇数或内部评分能够保证收录、引用或推荐。[S1] |
| Google 垃圾内容政策 | 同义主题治理、范围差异核验、编辑组织价值与分批发布 | 不用大量低价值关键词页替代内容建设。[S2] |
| Google 分页与索引文档 | 普通链接、合理分页、规范地址及索引控制 | 不把点击后才加载的按钮当作唯一内容发现路径。[S4][S5] |
| Schema.org 集合与列表定义 | 用标准语义描述专题和实际选文 | 结构化数据不等同于搜索平台的富结果或排名承诺。[S6][S7] |
| GEO 原始研究 | 对内容组织、来源引用和实际可见度进行可重复评估 | 研究结论存在实验范围，不能把提升比例直接外推到任意站点和平台。[P1] |

本轮于 2026-09-30 核对 Google 生成式搜索、评价和活动规范、参与控制与报告，以及三篇研究的公开说明。文中区分官方要求、研究观察及本项目的产品规则；未重新逐条验证所有历史链接或生产部署。

CMS 的“允许索引”、页面的“已发布”与平台实际收录或引用分别记录。站长工具和分析平台接入由部署方授权完成，不能从 CMS 状态推断外部平台资格或展示结果。

### 11.2 页面表达与抓取

每页一个清楚的专题 H1，分组使用有含义的标题，导读说明范围与阅读顺序；同义问法归入同一意图，避免大量重复 H2 或仅替换产品、对象及地区名称。

主体、分组、文章卡片、来源及分页链接使用 Blade 服务端输出。此选择沿用现有技术栈并降低读取依赖，不声称搜索引擎无法处理 JavaScript。折叠区域的正文保留在 HTML 中；关键内容不要求登录或点击后另行加载。

本方案不规定统一回答字数，也不要求为 AI 把段落拆成固定长度。实质结论应有必要上下文与证据；清晰的章节和链接首先服务读者。内容长度、模块数量和呈现方式由实际信息需要决定，不据此承诺搜索效果。[S1]

### 11.3 元数据只从一个公开读模型生成

拟由`TopicSeoPresenter`生成 Title、description、canonical、robots、OG 和 JSON-LD，交给现有主题头部输出；正文与结构化数据使用同一个有效公开集合。

| 数据 | 实现要求 |
| --- | --- |
| Title | 由专题名称、受控时效词和站点名称生成；人工覆盖后保留覆盖状态，长度与日期回退规则一致 |
| description | 默认取真实导读摘要，允许编辑，不堆叠匹配词 |
| canonical | 当前站点的稳定规范地址；不带预览令牌 |
| robots | 站点级限制优先，页面设置只能进一步收紧 |
| OG | 与页面真实标题、描述、地址一致；没有封面则省略相关字段 |
| 日期 | 首次发布、实质更新、有效期和复核分别来自真实记录；显示按站点时区，结构化数据用 ISO 8601 |
| JSON-LD | 仅包含当前可见的精选文章、顺序、标题与真实身份 |

必须检查活动主题已输出的 head，避免两份 Title、canonical、robots 或重复实体。现有`seo-head.blade.php`有站点级索引逻辑，应在统一决策上扩展，不在专题模板另加互相矛盾的标签。[C11]

### 11.4 URL 与索引矩阵

| 页面或状态 | HTTP 与公开策略 | canonical 与 Sitemap |
| --- | --- | --- |
| 有内容的频道及专题 | 200，站点允许时可索引 | 自指，符合条件时加入 Sitemap |
| 频道普通分页 | `/topics/page/{page}`，200，实际内容不同 | 每页自指，HTML 前后页链接；第一页归一到`/topics`，越界 404；默认仅频道首页进入 Sitemap |
| 尚未首次开放的空频道 | 不开放入口，公开请求 404 | 不进入 Sitemap |
| 已开放频道暂时无有效专题 | 200，公开维护说明，`noindex` | 不进入 Sitemap，不显示草稿标题 |
| 可选分类筛选或搜索 | 默认`noindex,follow` | 内容不同则自指，不批量提交组合 URL |
| 单纯跟踪参数 | 保留必要归因后规范化 | 指向无跟踪参数的同一内容地址 |
| 草稿或审核预览 | 授权访问，`noindex`、`private,no-store` | 不进入 Sitemap，无公开令牌链接 |
| 撤回、软删除或安全暂停的专题 | 公网 404，不返回旧正文 | 移出 Sitemap，清理回链和缓存 |
| 已确认永久移除且无替代 | 按明确删除策略 410 | 不统一跳首页 |
| 合并到真正承接同一意图的专题 | 301，目标必须有效 | 旧地址移出 Sitemap，内部链接修正 |

普通分页不能全部 canonical 到第一页。[S4] `noindex`只有在爬虫能读取时才可能被处理，不应同时禁止抓取后期待页面标签生效；草稿隐私由认证保障。[S5]

专题详情不接受任意过滤参数来生成新的文章组合。未知参数按白名单处理，不让随意拼接 URL 产生无限变化的公开内容。

### 11.5 保护原有路径与历史地址

源码固定链接保留段中尚未列出`topics`，因此正式加入保留路径之前，需要检查生产文章路径、分类 slug、既有静态页及安装主题路由是否已经使用该前缀。[C12]

如果已有冲突，保留专题草稿并列出具体受影响 URL，给出站点地址适配入口；先制定迁移或另选频道前缀的方案，不能直接抢占原有文章地址。新路由明确声明在文章通配规则之前，同时补齐保留路径校验。

同一站点的专题当前路径和历史路径使用统一`topic_paths`登记，数据库唯一约束覆盖专题地址命名空间。全站文章、分类、静态页及历史固定链接由既有 URL 治理加专题占用检查共同校验，专题表的唯一性不能替代跨资源冲突检查。改标题默认不改 slug；主动改 slug 时保留旧路径，旧路径通过专题 ID 解析最新有效地址，不形成多段 301 链。

slug 可使用经过安全规范化的中文或系统生成标识，不强制运营手填英文。统一处理 Unicode、长度、编码和尾斜杠；禁止路径穿越、保留段及不受控跳转目标。

专题改 slug 采用受控预检、影响确认与原子路径切换；确认绑定专题版本、站点地址代次和旧路径。预检后全站固定链接或域名配置改变时拒绝旧确认并重新生成报告。默认一期频道前缀固定为`topics`；部署冲突需要迁移或定制适配时，先完成该部署的地址方案再启用。频道前缀改动不作为普通运营设置。

### 11.6 Sitemap 兼容两种已有模式

现有系统有主站小规模内联 URL 集合及大站/托管站索引分片。新增专题后统一计算根 Sitemap 模式：文章、专题、首页和频道的实际可索引 URL 共同参与阈值判断。[C10]

| 模式 | 专题接入 |
| --- | --- |
| 主站小规模内联 | 根文件同时输出已有文章和合格专题，完整计算数量与字节限制 |
| 索引/分片 | 保留文章分片，新加`/sitemaps/topics-{page}.xml`；两类分片独立生成 |

根 Sitemap 和文章分片控制器必须使用相同模式判断。仅专题数量导致切换时，不能出现根文件已输出文章分片地址，分片却因原文章数量不足而返回 404。

需要 manifest 时，先生成可用边界再切换；暂时不可用返回明确的可重试服务状态，不输出假空结果。冷启动、阈值附近变化、禁用索引、撤回及域名变更必须测试。

按官方协议控制 URL 数及文件大小，`lastmod`只反映重要变化；不伪造每日更新，不把`priority`或`changefreq`当成 Google 权重调节器。提交 Sitemap 也不代表完成收录。[S3]

XML Sitemap 与现有文本 Sitemap 从同一资格集合取得当前站点的频道首页和合格专题，历史地址、分页页、草稿及安全暂停对象均排除。现有`llms.txt`可增加安全频道入口并复用现有输出方式，专题分页继续通过 HTML 链接发现。该接入只维护已有辅助文件的一致性，不作为 Google 引用前提。

### 11.7 结构化数据的最小集合

默认采用`CollectionPage`、`ItemList`及`BreadcrumbList`；复用已有站点组织实体，不重复制造不同 ID 的同一站点组织。[S6][S7]

活动专题默认仍是`CollectionPage`。只有页面聚焦一个真实、可核验的单一活动，并且正文可见活动名称、开始时间、结束时间、地点或线上方式、状态和唯一 URL 时，才按目标平台要求评估`Event`结构化数据；活动列表、参会指南或多场次集合页不标成单一`Event`，避免结构化数据与页面主题不一致。[S10]

`ItemList`的数量与顺序必须对应当前可见精选集合。安全移除文章后，正文、目录、计数和 JSON-LD 同步变化。页面中的文章卡片不能被误标为在专题页完整发布了对应 Article 正文。

`reviewedBy`和`lastReviewed`只有真实且适用本版本的复核记录时才输出，身份、职责与页面可见说明一致。内部匹配分和编辑评分不输出为`AggregateRating`，不伪造用户点评或平台背书；编辑评分与 AI 辅助评分只能作为标明来源的页面信息展示。

所有 JSON-LD 通过安全序列化生成，处理脚本结束标签等边界；运营与模型不能直接上传可执行的结构化数据脚本。
来源、依据和审核信息可以在可见 HTML 中以链接和文本呈现；只有 Schema.org 或目标平台定义的标准属性进入 JSON-LD，不把内部评分、匹配理由或自定义证据字段伪装成标准属性。

### 11.8 FAQ、AI 文本文件与爬虫策略

常见问题模块按用户真实需求启用，默认不作为发布必填项。是否使用特定问答标记、平台是否展示对应富结果，以实施时官方支持范围为准；本方案不把 FAQ 标记作为流量或 AI 引用保证。

`llms.txt`等辅助文件不列为一期专题功能的发布前提。部署方已有明确使用场景时，可单独评估与配置；此类文件不能替代可访问的页面、正确的权限控制和有价值的内容。[S1]

继承站点所有者对搜索抓取、训练用途及用户触发访问的策略。现有`/*?*`规则通过无参数分页适配；筛选参数被禁止抓取时，`noindex`只能作为页面声明，不能声称爬虫已读取处理。专题上线不自动更改全站 robots、WAF 或训练访问策略。日志中的 User-Agent 仅作访问线索，不能证明平台引用。

截至本轮核验，Google 已提供 Search Console 的 Search generative AI control，用于管理站点及继承属性的生成式搜索参与；该控制与普通搜索索引及训练控制分别管理。[S11] 站点试点清单记录属性范围、实际参与状态、核验时间和所有者授权。未取得账号证据时写“未核验”，不从 CMS 的可索引状态推断已参与，也不由专题模块修改外部账户设置。

### 11.9 GEO/AEO 目标、研究依据与可测量案例

本方案把专题页的搜索价值拆成三个可观测阶段：

```text
可发现性：页面能否被抓取、索引并进入候选来源
引用选择：AI搜索是否选中页面作为来源
引用吸收：回答是否使用了页面的定义、事实、比较、步骤或边界
```

这三层不能用一个“AI 评分”替代。Google 的生成式搜索指南明确指出，AI 功能依赖搜索索引、检索增强生成和查询扩展，页面需满足常规抓取与索引条件；无需“AI 专用”标记；技术索引资格与站点参与设置分别核验，也没有索引或展示保证。[S8] 页面结构化摘要的价值在于让人和机器更容易理解实体、范围、证据和更新时间，不能把结构化数据写成隐性排名信号。

研究证据转为以下产品规则：

| 研究或案例 | 观察 | 在专题页中的落地 |
| --- | --- | --- |
| GEO-bench 与 Perplexity 实验 | 引用、相关引文和统计信息在实验中提升可见度，效果随领域变化 | 允许关键事实、数字与来源卡片，要求真实依据；按领域做试点，不承诺固定提升比例。[P1] |
| 2025 跨引擎比较研究 | AI 搜索在来源类型、语言、时效和问法上存在明显差异，第三方来源常有更高权重 | 站内专题承担可引用的第一方资料，运营同时记录第三方证据和平台差异，不能只测一个引擎。[P2] |
| 2026 引用选择与吸收研究 | 引用数量与页面对答案的实际贡献可能分离；高影响页面常有清晰结构、语义对齐、定义、数字、比较和步骤 | 评价引用是否真正支撑回答，结构化摘要与正文保持证据一致，分别记录引用选择及观测使用，保留吸收测量的适用边界。[P3] |
| Google 生成式搜索官方指南 | 价值、独特、以人为本的内容、可抓取正文和基础 SEO 仍是长期基础 | 专题内容先服务读者，再使用语义 HTML、内链、规范 URL、Sitemap 和可选结构化数据。|

研究中的“提升 40%”属于特定基准、模型和实验设置，不能直接外推为本站流量或排名承诺。公开报告必须写明平台、时间、语言、问法样本和评价规则。

一期试点采用“上线前基线＋同期实验组和保持组”：基线是时间窗口，实验组和保持组是同期页面集合。首批试点选择 5 个可比主题配对，实验组发布 5 个专题，保持组使用原有页面且不启用新模块；内容量不足时减少配对并标记探索样本。所有页面执行相同来源与公开资格检查，保持组也不能保留已失效或误导信息。

按每个主题预先冻结 5 种意图问法，覆盖定义、比较、步骤、时效及适用范围。每个表面在每个基线或观察窗口内各重复 3 次，使用独立新会话、相同语言/地区、同一登录和检索模式；记录平台及模型版本、答案、来源 URL、关联陈述、时间和未完成原因。Google AI Overview、AI Mode 及 Gemini 作为不同表面分别统计，ChatGPT 搜索及 Perplexity 也分别统计。可用表面不足时报告实际范围，不推断缺测结果。

观测至少覆盖上线前 7 天和上线后 28 天，每 7 天采样一次；抓取或收录未完成时保留等待记录。问法集合的 20%留作评估，不能据其结果调优；按意图分组汇总，重复采样不当作完全独立用户样本。同批修改多个模块只能评估模块组合的关联变化，无法从结果单独归因于评分、星形、标签或标题。要判断单模块影响，下一轮固定其余内容再比较。实验组与保持组记录同期内容修订、外部报道和平台变化。

| 指标 | 分子与分母 | 证据和限制 |
| --- | --- | --- |
| 页面索引覆盖 | 被证据确认索引的专题 URL / 实际核验 URL | URL 检查或目标平台证据；另报计划 URL 数及未核验数，HTTP 200 不代表收录 |
| 检索出现率 | 搜索结果中出现目标规范 URL 的有效采样 / 有效检索采样 | 保留结果和 URL；不与页面索引覆盖混为同一比例 |
| 引用选择率 | 回答明确引用目标规范 URL 的有效答案 / 有效答案 | 同时报告搜索触发比例；未触发 AI 答案单列，超时/封禁不记为零引用 |
| 引用支撑准确率 | 来源可支撑关联陈述的引用陈述对 / 已复核引用陈述对 | 记录来源版本、陈述和支持片段，失效或无法读取单列 |
| 观测使用率 | 同时引用目标 URL 并使用其中事实/步骤/边界的答案 / 引用目标 URL 的答案 | 允许作为吸收的观测代理；通用事实重合或相似措辞无法证明真实来源贡献 |
| 问法稳定性 | 同一意图各次采样的引用出现、来源集合和支持正确性分布 | 按表面分别报告，给出次数及不确定性，不伪造平台内部信号 |
| 读者结果 | 专题至文章的有效点击 / 按同一统计口径的专题访问 | 指标附实际数据条件；没有可靠停留事件时省略停留时长 |

规范 URL 归一遵循实际重定向和 canonical，不能把同域不同页或不同语言页面合并成命中。所有比例展示原始计数和有效分母，失败、缺测、未收录及无 AI 回答分别记录；没有有效样本时显示“暂无可计算结果”。

[P3]中的吸收框架用于启发测量设计。公开答案与页面文本比较只能得到使用线索；因果贡献需要反事实或其他专门实验。本期报告采用“观测使用”，保留选择与支撑数据，不对某页的真实因果贡献作数值承诺。

### 11.10 主题和品牌中立

Title、面包屑、Schema 实体、OG 字段及链接统一从当前站点和专题版本生成，不保留任何演示组织或占位地址。主题示例中的`example.com`不得进入生产 Sitemap、canonical 或结构化数据。

所有站点使用相同的 SEO 输出契约；不同站点的组织实体、品牌名称与文章集合分别解析。复制页面结构不等于复制其他站点的来源、审核记录或内容权利。

## 12. 数据模型与一致性

### 12.1 一种专题，扩展现有任务

保持 Laravel 单体应用，核心为 `Topic`、`TopicRevision` 和版本选文关联。人工与自动生成共享草稿结构。现有 `Task` 增加内容类型、专题设置与目标站点，`TaskRun` 增加专题结果；调度、身份和用量记录复用现有能力。

不把 AI 内容另存为竞争的公开正文。生成结果先进入运行记录，再原子写草稿；公开内容只来自公开版本。换模板不复制专题，维护任务只产生新版本。

### 12.2 拟新增的 11 类记录

表名为开发设计，未代表当前已实现；现有通用存储满足同一契约时可以复用。

| 记录 | 职责与关键约束 |
| --- | --- |
| `topics` | 站点、稳定主题键、草稿、草稿版本、公开指针、负责人、来源任务/标题/批次、自动维护授权与暂停、公开时间、内容及安全代次、软删除 |
| `topic_revisions` | 不可变的标题、导读、摘要、分组、依据、时效、评分、模板选择和公开范围；内容及依赖哈希 |
| `topic_revision_articles` | 有序选文、分组、卡片快照、来源内容哈希；同版本文章 ID 唯一 |
| `topic_article_overrides` | 持久排除和人工锁定，记录操作者及版本；当前顺序仍以草稿为准 |
| `topic_build_runs` | 手工匹配、AI 生成及自动维护运行；可在创建专题前存在，绑定站点、任务运行、标题、轮次、租约、输入版本、阶段、结果、错误和使用量摘要 |
| `topic_candidates` | 运行内候选、相关度解释、分组建议、来源哈希与资格；可重建，不作公开正文 |
| `topic_reviews` | 真实人工/专业审核及 AI 检查类型，绑定版本、内容、依据和策略；无审核要求不强制创建人工记录 |
| `topic_paths` | 站点内当前、历史和保留路径的统一登记，地址不可抢占 |
| `topic_import_batches` | 输入、逐行结果、来源行键、处理方式、进度、私有报告、幂等键及保留期限 |
| `topic_suppressions` | 受影响文章、摘要块或核心主张的即时失效与恢复记录 |
| `topic_operations` | 生成/发布/撤回等确定动作的请求、幂等、结果及派生更新回执 |

`topic_build_runs` 的标题占用和生成结果同时提供专题标题使用统计，无需再增加第二套标题消费表。自动任务运行关联 `task_run_id`，手工或批次运行分别关联操作者/批次。模型调用详细账本仍沿用现有记录。

### 12.3 现有模型的增量字段

| 模型 | 拟增加或调整 |
| --- | --- |
| `Task` | `content_type` 默认 article、`topic_limit`、`topic_site_key`、固定结构 `topic_config`；既有 `automation_version` 继续失效旧运行 |
| `TaskRun` | `content_type`、`topic_id`，`article_id` 保留；输出访问器按类型返回结果 |
| `Title` / `TitleLibrary` | 专题使用与结果查询，不改变原文章使用字段；统一标题指纹，专题入口可筛选有适用标题的库 |
| `Prompt` | 允许 `type=topic`，内置专题默认规则，文章 type 保持原语义 |
| 模板包与修订 | 专题页面映射、可选 `topic-view` 契约及布局目录，文件仍按现有清单与校验和管理 |

保存未配置完整的专题任务时保持暂停并列出配置入口。当前 PostgreSQL 初始表把标题库、提示词和模型字段设为非空，SQLite 测试表允许为空；迁移应统一为可空外键，并用类型/状态约束保持文章任务所需字段完整、已激活专题任务所需字段完整。专题的缺配置暂停记录允许为空，不能用占位模型或虚构 ID 保存。表单、管理 API/CLI、调度和激活检查共同遵守此约束；回退先处理不完整记录。

任务的“保存草稿”“审核后发布”和“自动发布”由 `topic_config.after_generation` 作为单一事实来源，`need_review` 及计划发布行为由类型适配器派生，不同时维护两个可冲突开关。专题草稿限额独立于文章库存计算。

### 12.4 草稿和模板数据

固定草稿结构包括：主题名称与范围、SEO 覆盖状态、模板键、文章范围、选文、分组、导读、结构化摘要、标签、依据、可选基础信息、可选时效、可选评分、字段来源和人工锁定。

冻结后每个字段只有一个权威存储位置。内容 JSON、摘要、分组、时效、评分和关联文章保持固定分工，公开指针只引用本专题版本；工作草稿、审核绑定版本、公开快照和历史记录按专题分别管理。审核、运行和抑制状态不能为了更新日志而改写不可变内容。

### 12.5 一致性约束

- 站点键非空，为 `primary` 或明确的托管 Profile 标识，不能与渠道 ID 混用。
- 同站稳定主题键具有防重复约束；已删除/撤回主题保留记录，任务跳过或要求明确恢复。
- `task_run_id` 对自动运行输出唯一；标题首建占用以站点、任务、标题、轮次唯一，主题键再防同站跨任务重复。
- 业务创建、标题成功标记和运行回执同事务，重试可以找回原草稿或原公开版本。
- `topic_id + revision_no`、`revision_id + article_id`、`site_key + normalized_path` 分别唯一。
- 任务配置、草稿、人工规则、语料和来源版本均可比较，旧运行不能覆盖较新输入。
- 幂等键绑定动作、站点、执行主体和请求哈希，不同输入不能重用同一键。
- 可表达的唯一性由数据库落实，并使用真实 PostgreSQL 验证并发；语义判断不只依赖“先查后写”。

哈希只包含影响展示、依据和授权的语义字段。浏览量、内部日志、模板纯排版和重复执行时间不触发内容重审。运行原始片段、候选及导入报告按既有私有存储与保留策略清理；敏感内容受控清理后不能经历史恢复重新公开。

## 13. 调度、重试与运行保障

### 13.1 复用现有任务基础设施

现有任务调度根据内容类型路由到文章或专题执行服务。专题生成、维护、批量导入和费时匹配使用队列；普通保存、模板切换和页面渲染无需等待模型。

专题任务先处理自己已到期的计划发布，再取题生成。`draft_only` 不进入发布扫描；`review_then_publish` 只有实际审核完成的绑定版本可进入计划发布。调度、任务启停、配额和清理都按类型计数，旧文章扫描器不接管专题。

队列使用项目现有队列部署方式，实施前核对 worker 订阅。任务状态持久化，离开页面后仍能查看实际阶段：等待、匹配、选文、生成内容、保存、发布或待处理。不展示没有可靠依据的百分比。

### 13.2 执行身份与调用

模型选择复用现有执行身份、模型访问解析器和调用网关；每次运行及提交前核验当前权限。默认使用明确可用模型，授权备用模型可以按现有策略切换，不能换到操作者无权访问的配置。

记录请求模型、实际模型、提示词版本、规则、来源版本、调用次数、失败类型与实际用量。按模型运行时上下文和输出上限裁剪材料，保留截断记录。每日数量与调用预算沿用现有任务限额，默认串行构建，避免并发突增。

技术错误最多按现有任务配置重试，初始上限 3 次；无效结构允许 1 次 AI 修正。预算在修正和备用调用前重新核对。模型不可用时任务可保存，执行等待配置并给出入口；人工编辑与查看继续可用。

专题内容生成与独立事实校验的单次请求均最多等待 120 秒。每次调用按本轮剩余时间缩短等待，本轮累计调用时间预算为 240 秒；模型调用锁的有效期覆盖最长请求及处理余量。较慢的校验可以继续完成，超时仍保留真实失败记录并提供重试，未通过校验的内容继续留在草稿。

### 13.3 阶段持久化与幂等

每个运行保存确定输入、来源、标题占用、选文结果、生成结果和最终业务回执。已经保存有效结果后，发布失败仅重试发布，不能再调用模型或再建专题。

提交前检查租约和任务配置版本。暂停、取消、超时重占用或人工编辑后的旧 worker 失去提交资格。占用恢复、业务提交和回执写入保持一致，避免任务明明已生成却又重复消费标题。

取消在安全阶段边界停止。外部调用可能已经产生费用，结果按取消和版本规则保存为运行资料或未提交建议；不能声称取消意味着模型未执行。停止或改配置使运行代次变化，提交前必须比较；被取消的旧操作不能消费标题、创建正式结果或发布。保留运行资料与已确认完成项。失败行继续关联原草稿，用户可查看或重试。

### 13.4 等待状态和自动维护

没有文章的标题记为等待内容，保留标题占用状态和原因，不阻塞其他可生成标题。相关新文章发布或用户重试时重新检查；每日有限对账可补偿遗漏，避免无限循环调用模型。

标题库用完显示等待新标题，配置失效显示等待配置。等待状态与技术失败分别计数；空库和耗尽都不回绕取题、不制造备用标题，保存任务仍可完成。批量与任务结果中明确列出下一步，不能以“已全部完成”掩盖等待项。

自动维护合并同一专题短时间内的来源事件，遵守任务计划和发布间隔。每个专题只保留一个有效维护运行，人工修改、撤回和任务暂停均在提交前重新检查。

### 13.5 站点上下文

后台和队列输入保存明确站点键，每次执行重新解析当前授权和公开域名。使用显式站点查询与 URL 服务；适配可变 `CurrentSite` 时在任务边界建立并于 `finally` 清理，拒绝未解析上下文。

同一个长驻 worker 连续处理两个站点必须测试。托管 Profile 与分发 Channel 的 ID 不混用，不能根据管理页面域名猜公开站点。[C7][C8][C9]

### 13.6 公开读取与缓存

公开请求读取已发布版本及有效来源集合，不现场匹配全库、调用模型或抓外部来源。正文、摘要、目录、计数、首页卡片和 JSON-LD 来自同一有效读模型。

发布指针、来源资格和抑制使用主库或已证明满足一致性的读取，ETag/304 同样重新检查。缓存键包含站点、语言、专题版本、主题修订、固定链接、时间与安全代次；有效期不能越过下一时效或评分边界。

专题 HTML 默认不启用长时间共享边缘缓存。预览采用认证及 `private,no-store`，PWA/Service Worker 不得误缓存草稿。撤回时正文、摘要、JSON-LD、首页、频道、文章回链和 Sitemap 一并失效；普通队列延迟不阻碍来源撤回的立即执行。

公开回执区分业务成功与派生更新状态。Sitemap、通知和缓存重建可以重试，记录失败，不能声称数据库提交即证明搜索引擎已更新。

### 13.7 性能和锁顺序

前台批量预取最多 24 篇选文及其作者、分类和资格，避免 N+1。首页只查询少量公开专题，不加载正文。候选和原始正文不全量发到浏览器。

执行短事务按现有任务锁序取得任务/运行占用，再处理必要的地址和专题锁。发布服务不在持有专题锁时追加任务或源文章锁，来源通过一致性版本比较并由读取检查补偿并发窗口。地址操作沿用站点地址锁后专题锁的顺序，来源失效按专题 ID 稳定顺序登记。实施前绘出实际各调用路径锁序，真实数据库验证取题、发布、撤回和改址并发。

## 14. 模板体系、数据标签与接口

### 14.1 模板支持的完整页面

| 页面或组件 | 拟定文件 | 说明 |
| --- | --- | --- |
| 首页 | `home.blade.php` | 增加专题导航与首页专题模块位置 |
| 专题列表 | `topics/index.blade.php` | 频道说明、专题卡片、普通分页 |
| 专题详情 | `topics/show.blade.php` | 调用选定详情布局，输出统一有效数据 |
| 详情布局 | `topics/templates/default.blade.php`、`guide.blade.php`、`roundup.blade.php` | 标准聚合、阅读指南、资讯盘点 |
| 首页模块 | `partials/topics-home.blade.php` | 可在首页复用，空集合隐藏 |
| 专题卡片 | `partials/topic-card.blade.php` | 首页、列表及相关推荐共用 |
| 详情组件 | 摘要、基础信息、分组、评分、来源和目录组件 | 按当前模板体系组织，数据缺失时省略 |
| 文章回链 | `partials/related-topics.blade.php` | 最多 3 个有效高相关专题 |

默认主题提供系统视图，命名主题使用对应主题目录。模板开发文档明确页面布局、变量类型、可选字段、兼容回退、SEO 头部职责和转义方式。

一期交付三种可用详情布局。列表及首页模块继承活动主题设计，可由主题包定制；普通用户从支持目录选择模板，不填写文件路径。专题模板的选择仅在当前活动主题和其兼容组件范围内，避免将另一个主题的完整头尾混入当前站点。

### 14.2 调用契约与“模板标签”

模板沿用 Blade 和现有组件机制。“模板标签”指可调用变量、循环和组件；专题的内容标签是另一个明确字段。无需新增自定义脚本语言、任意查询标签或第二套模板解析器。

服务端生成 `TopicView` / `TopicListView`，一次提供页面所需的已过滤数据。以下名称是拟定契约，实施时保持统一并补充类型定义与示例。

| 调用变量或字段 | 类型与用途 | 缺失行为 |
| --- | --- | --- |
| `$topicView` | 专题详情展示对象 | 未授权或未公开时不能建立公开对象 |
| `$topicList` | 分页专题卡片集合 | 频道空态按公开策略处理 |
| `$homeTopics` | 首页专题卡片列表，默认最多 3 条 | 空列表，模块隐藏 |
| `$topicNavigation` | 当前站点频道标题与规范链接 | 未开放时不显示导航 |
| `title / base_title / url` | H1、稳定主题名及规范 URL | URL 由服务解析，不接受模型提供 |
| `intro / summary` | 导读、结论、关键事实、范围和阅读建议 | 可选摘要项省略，导读必须有效 |
| `tags / basic_info` | 内容标签与允许的键值信息 | 空列表，不显示无依据字段 |
| `sections / articles` | 稳定分组与已过滤有序文章卡片 | 空组隐藏，未分组文章不能丢弃 |
| `article_count` | 当前有效不同文章数 | 从读模型计算，不用模型声称数量 |
| `dates` | 首发、实质更新、实际复核、整理和检查日期 | 无真实记录的项目省略 |
| `freshness` | 标题词、范围、有效窗口与当前提示 | 无依据不输出时效宣称 |
| `score` | 编辑/AI 来源、总分、维度、权重、依据、有效期 | 未启用或失效时为空 |
| `sources / review_info` | 公开来源及真实检查/审核说明 | 私有路径和内部身份隐藏 |
| `related_topics / action_entry` | 有效相关专题及已有后续入口 | 无合适结果时隐藏 |
| `seo` | Title、description、canonical、robots、OG、JSON-LD | 交由既有统一 head 输出一次 |
| `template_key / schema_version` | 允许的布局键、契约版本 | 默认布局，未知键不给任意路径执行 |

模板仅使用已提供变量与标准组件。专题卡片、摘要和评分组件支持复用；日期和星形使用统一格式器，不允许每个主题各自计算。模板不直接查询全库，不绕过站点与来源过滤，不现场发起 AI 请求。

文本默认转义，富文本使用统一净化结果。JSON-LD 由安全序列化生成。私有内部字段从展示对象中去除，减少模板作者误用的机会。

### 14.3 能力声明与主题包

保留现有 `site-theme-view-resolver=1` 契约；增加可选 `topic-view=1`。旧包缺少专题契约时原有页面仍兼容，新包声明专题契约时系统检查支持版本与必需视图。

主题清单新增专题能力、可用布局及首页模块声明。布局 ID 是白名单键，关联包内的确定视图；由模板目录读取，不从用户字符串拼任意文件路径。专题数据契约变化按版本管理，不能静默更改字段含义。

`SiteThemePackageGuard` 不能只往原平面页面数组添加名称。建立页面键到视图相对路径的明确映射：保留 home/category/article 等旧项，新增 `topics-index → topics/index.blade.php` 与 `topics-show → topics/show.blade.php`。首页局部组件属于依赖文件，单独声明能力，不当作完整页面。

同步更新包导出、检查、安装、依赖扫描、页面展示、校验和、兼容说明及管理界面。使用专题的包在旧系统上给出“请先升级 GEOFlow”的明确提示，新系统可以读取旧包。往返导出安装后布局、首页模块和依赖完整保留。

### 14.4 旧模板与不可变修订

非修订主题缺少专题视图时，解析器可以采用系统默认专题组件并沿用可用的主题外壳。首页模块必须有真实插入点，不能仅宣称有变量就认定已在首页展示。

不可变主题读取器只接受清单内视图。兼容构建必须将缺失专题视图、组件及完整依赖闭包加入新修订清单，资源 URL 绑定同一修订；不能在运行时越过清单偷偷读取新增默认文件。

标准主题升级同时适配首页和文章回链。自定义主题保留原页面文件，系统可生成适配草稿并预览；涉及已有首页文件改动时，通过现有模板管理的预览/启用操作完成。运营不用判断校验和、清单或文件版本。

切换兼容修订前检查首页、分类、文章、专题列表/详情和资源的实际渲染。失败保留原活动主题，提示具体问题；回退恢复原绑定，不删除专题内容。已经公开专题时，回退到缺少专题能力的主题必须使用验证过的兼容回退修订，防止专题整体变成渲染错误。

### 14.5 模板生成能力

更新 `ThemeScaffoldWriter`、生成蓝图和合规检查，使新生成的网站模板默认包含专题列表、详情、首页模块及契约。已有 AI 模板编辑能力按同一规范处理专题，不另建专题专用模板生成平台。

生成模板使用虚构示例数据检验布局，真正渲染时读取站点展示对象。页面中不留示例日期、8.5 分或虚构身份。模板布局能力与专题内容生成能力分别记录，模板生成不会发布内容。

### 14.6 服务与接口边界

最小职责分为：站点文章资格、匹配、AI 组合、专题草稿/版本、发布、公开读模型、模板呈现。复用现有任务与模型网关，类按实际项目规范组织，不为每一步创建独立子系统。

后台 `admin.topics.*` 包含列表、新建、编辑、保存、预览、AI 生成、匹配/采纳、发布、撤回、批量/导入、运行结果、历史恢复及回收站。配置入口跳现有站点/AI/模板页面。

异步动作返回运行 ID 与状态查询地址；确定发布动作返回回执 ID；保存、采纳和发布携带预期版本及幂等信息，服务器生成授权哈希。响应按类型区分生成结果和发布结果。

任务后台与已有管理 API/CLI 的类型、输出和校验必须同步，旧文章请求不带类型时仍按 article 处理。专题类型的未适配调用明确拒绝，不创建错误文章。该兼容工作服务现有管理能力，不新增面向第三方的开放专题 API。

公开路由包括 `/topics`、`/topics/page/{page}`、`/topics/{slug}` 及专题 Sitemap 分片；路径预检和具体索引策略见第 11 节。路由位于文章通配规则之前，管理前缀沿用现有配置。

<a id="s15"></a>
## 15. 权限与内容边界

### 15.1 沿用现有账号能力

复用管理员身份、站点授权及现有内容编辑、审核、发布和设置能力，通过 Topic Policy 适配。创建任务并选择自动发布需要拥有目标站点的发布能力；用户点击启动即建立有限任务执行授权，执行时仍检查账号和权限是否有效。

有编辑能力但无发布能力的用户可以创建草稿，任务处理方式仅显示可用项。普通专题不强制职责分离；站点已有策略时沿用其要求。系统自动发布身份不能被前台标为专家。

### 15.2 基本保障自动执行

站点归属、CSRF、输入校验、文件净化、私有报告、操作审计和限额使用现有基础设施。模型拿到的材料限定在本站可公开来源及该次必要片段，私有知识库不会因具备后台读取权限而自动对外发布。

普通专题生成不开放任意出站抓取。未来使用外部资料时单独处理 URL 白名单、重定向、内网地址和授权；不通过 AI 输出的 URL 访问内网。模板仍按既有受信安装与依赖规则管理，普通运营不上传可执行模板代码。

源文章已撤回、权限收紧、数据清理或明确风险时，相关公开内容立即停止展示。用户看到实际影响及重组入口，内部一致性检查不扩展成额外的日常审批流程。

## 16. 开发工作包与回退

### 16.1 一期按一套完整功能交付

该范围涉及超过 8 个文件和多个服务，按下面顺序实施。顺序用于降低开发风险，各工作包均属于本次确认范围，模板与自动任务不能被移出首期。

| 顺序 | 工作包 | 可验证结果 |
| --- | --- | --- |
| 1 | 核对当前任务、文章、站点、模板、URL 和部署差异 | 记录接入契约、旧任务默认类型和迁移/回退方式 |
| 2 | 专题数据、草稿/公开版本、资格与可靠发布 | 手工选两篇文章可形成正确隔离的公开专题 |
| 3 | 专题列表、单个/批量创建与设置引导 | 用户在现有内容管理中完成完整手工流程 |
| 4 | 模板变量、三种详情布局、列表、首页与包升级 | 默认/内置/自定义兼容路径实际渲染，模板包往返不丢文件 |
| 5 | AI 召回、选择、摘要、依据检查和局部再生成 | 真实模型配置可生成可编辑草稿，失败能恢复 |
| 6 | 任务类型、标题使用、调度与自动发布/维护 | 标题库按计划生成专题，旧文章任务保持原行为 |
| 7 | SEO、Sitemap、时效、评分、来源失效和运行观测 | 公开数据一致，撤回及时，时间和记录真实 |
| 8 | 综合验收、试点和上线说明 | 功能、视觉、并发和升级检查完成后整体交付 |

先跑通标准站点，再覆盖托管站及主题修订。实现期间可以在未公开环境逐步验证，正式用户入口按完整可用版本开放。

### 16.2 核验方式

开发后执行实际仓库要求的格式、构建、PHP 测试、管理 API/CLI 契约及适用浏览器流程。任务类型、取题/结果、版本并发和缓存失效需要有行为验证，不能只测试新增类是否存在。

AI 自动测试使用 SDK 测试替身及固定来源，防止意外外部调用；另进行授权的少量真实模型验收，记录来源、模型和输出限制。[S13] 模板检查验证真实渲染和页面行为，不能以能编译代替首页已展示专题。

真实 PostgreSQL 验证并发取题、重复回执、任务暂停、人工修改、来源撤回及地址切换。视觉检查覆盖后台原样式与参考页信息结构，使用隔离测试浏览器，不改变用户现有浏览器视口。

### 16.3 上线与回退

先迁移兼容数据与旧任务默认类型，再部署新代码和受支持模板，最后开启目标站点展示。标准主题适配随升级完成；自定义主题适配在当前模板页面完成并保留原版本。

自动生成和前台展示开关分别控制。出现生成问题时暂停专题任务，已公开安全内容继续访问。模板问题回退到上一兼容修订；内容问题恢复经过当前来源检查的旧内容版本。

数据库回退前停止新专题任务，保留专题及标题使用记录，不执行破坏性删表。任务字段恢复非空前处理未配置完整的暂停记录，不可通过虚构外键强行回退。旧二进制回退需要明确如何隐藏并停止新类型任务，避免把专题任务误当文章任务。必要时保留兼容代码，仅关闭新增入口。URL、Sitemap 和缓存按实际回退方式同步。

### 16.4 首批试点

用 5 至 10 个真实有文章支撑的主题覆盖：手工、批量、标题任务、模板切换、自动发布、按需审核、缺文章、缺配置及来源撤回。先完成产品体验与内容检查，再扩大标题库数量。

试点记录生成成功率、用户编辑量、等待原因和发布结果。GEO 观察属于独立证据采样，不作为创建专题的前置条件，方法见第 11 节。

### 17.10 用户体验验收

邀请实际内容运营走查单个生成、批量生成、标题库任务、移除文章、修改已发布专题、缺配置恢复和来源撤回处理。记录是否需要讲解、是否误删文章、是否混淆草稿与公开版本、能否找到失败原因及返回原位置。前台再检查时效标题、结构化摘要、评分卡、星标文本替代、标签、基础信息和来源审核模块，确认缺失事实会省略，日期语义清楚，移动端阅读顺序合理。普通创建与任务设置各使用一张表单，普通流程不要求打开高级规则、输入 slug 或评分参数，也不要求理解数据库版本；完成率与操作次数由走查实际记录。

## 附录 C：典型场景

本节主题、数量和站点均为虚构示意，实际内容由目标站点提供。

### C.1 手工与 AI 共用专题

用户新建“产品使用入门”，点击 AI 生成。系统从本站已公开文章中选择 6 篇，分为“首次设置”“常用功能”“常见问题”，提供摘要和阅读顺序。用户删除一篇、调整两篇顺序、修改导读，再点击发布。

公开页使用选定模板展示 5 篇文章。AI 的检查记录如实标注，未启用评分和人工复核时不显示对应模块。首页自动出现该专题，文章页按相关性显示回链。原文章保持原地址和正文。

### C.2 标题库自动生成

用户创建专题任务，选择含 10 个标题的库、全站文章范围、默认生成规则和标准聚合模板，处理方式为自动发布，每小时生成 1 个。

启动摘要明确这些设置。实际运行中，7 个主题有充分相关文章并发布，1 个同主题已存在被跳过，2 个等待补充文章。任务结果分别显示并链接可编辑草稿或公开页，不能把等待项说成失败重试后已发布。

文章任务也在使用同一个标题库时，专题使用计数独立，不影响文章剩余标题。某次发布响应超时，系统查询原回执后展示已发布结果，标题不再次消耗。

### C.3 资讯盘点与时效词

用户选资讯盘点布局，允许加入实际整理月份。9 月完成新的内容整理时，标题可以显示“2026 年 9 月整理：示例工具使用指南”，页面同时说明真实整理日期。

任务到 10 月未产生实质新内容时，标题仍保留 9 月。若要求“截至 10 月有效”，系统检查来源是否确实覆盖该时间，缺少依据时保留基础标题或整理日期表达。价格、访问状态、活动实际举办情况和专家复核不能根据当前日期推断。

### C.4 自定义模板适配

某站已使用自定义首页与不可变主题修订。系统保留原页面，生成带专题列表、详情和首页模块的兼容修订，并在现有模板页面提供预览。模板管理员查看首页模块位置和专题布局后启用。

启用后同一个专题可以切换标准聚合、阅读指南或该主题声明的其他布局，内容与来源不变。导出模板包再安装到支持专题契约的实例，布局和依赖仍完整。回退采用已经验证可展示专题的兼容修订，专题数据继续保存。

### C.5 自动维护与人工修改

用户为既有专题开启自动维护并保护人工修改。新文章发表后任务补充一篇相关选文，并更新未锁定摘要；用户修改过的导读保持原样，系统提供新建议。

随后一篇来源文章被撤回，相关卡片和依赖文字立即停止展示。维护任务选择有效替代、生成新版本并按已授权方式发布。用户主动撤回整个专题时，维护停止，任务不能自行把该专题恢复公开。
