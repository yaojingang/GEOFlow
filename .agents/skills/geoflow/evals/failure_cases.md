# GEOFlow Failure Cases

- Selected a remembered route or CLI command without inspecting the target workspace.
- Treated an admin operation as an API v1 capability when no matching route exists.
- Changed product code while following the operations-only safety boundary.
- Edited an active theme in place when a preview fork or reviewed homepage payload was available.
- Synced a default-site module to a channel target package without checking `supported_modules`.
- Added backend fields or public modules without migrations, validation, localization, permissions, or tests.
- Claimed a legacy PHP preview was compatible with the current Laravel theme contract.
- Printed tokens, channel secrets, provider keys, passwords, or personal lead details.
- Reported success without persisted readback, route rendering, test output, or capability evidence.
- Resent an uncertain task-enqueue request after a missing receipt, deleted its journal, or generated a new request ID without business reconciliation and explicit authorization.

- Used an old wildcard token for Updater, guessed v2 support from a client class, or fell back to v1 after a rejected v2 submission.
- Recreated a plan during status polling, resent an uncertain Updater request after 404, or changed its ID without reconciliation and explicit authorization.
- Exposed a password or OTP in arguments/output, saved credentials with group access, or edited the local journal to bypass a request guard.
- Called host success with held background work complete, or described rolled_back as a successful target upgrade.
- Used full restore to undo a theme field, selected a historical restore point through the restricted remote workflow, or claimed unperformed native architecture rehearsal.
